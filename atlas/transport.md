# Переселение картинки с доказательством

64 точки открытой спирали превращаются в контур звезды. Каждый источник получает ровно одну отличную цель. В README работает GIF; полноценный стенд запускается из [ZIP](../assets/transport/bench.zip) через `file://`, без сервера, библиотек из CDN и сетевых запросов. В GitHub README JavaScript не исполняется.

## Что именно оптимизируем

Координаты целочисленные; `c[i][j] = (x_i-X_j)^2 + (y_i-Y_j)^2`. Собственный primal-dual алгоритм кратчайших увеличивающих путей для задачи назначений работает за O(n³), хранит O(n²) матрицу. Все вычисления точные, без float-оптимизатора. Генератор использует sin/cos только для получения округлённых координат; источником истины для сертификата служит опубликованный problem.json.

| Метод | Сумма квадратов расстояний |
|---|---:|
| Ближайшая свободная цель, источники по порядку | 62 850 |
| Глобальное назначение | 47 854 |
| Доказанная двойственная нижняя граница | 47 854 |

Жадный результат на 31,34 % дороже оптимума **в этом примере**. Это не универсальная оценка алгоритма. При равенстве жадный выбирает меньший индекс цели; порядок источников влияет на результат. Оптимум может быть не единственным. Квадраты расстояний — не сумма евклидовых длин. Линейное движение частиц не гарантирует отсутствие столкновений и не учитывает препятствия.

## Почему проверка доказывает оптимальность

Сертификат содержит перестановку `assignment` и целые потенциалы `u`, `v`. Независимый `verify.py` не импортирует оптимизатор, заново строит матрицу из координат и проверяет:

1. Назначение — перестановка 0…n−1.
2. Все n² неравенств `u[i] + v[j] <= c[i][j]`.
3. Равенство на каждом выбранном ребре.
4. Стоимость назначения равна `sum(u) + sum(v)`.

Для любой перестановки сумма стоимостей не меньше суммы потенциалов (каждый потенциал встречается ровно раз). Наше назначение достигает границы, следовательно оно оптимально. Здесь проверены 4096 неравенств, разрыв — 0. Проверка O(n²) не повторяет поиск назначения. Неподходящий сертификат отвергается; изменение потенциала на единицу ломает доказательство. Кнопка стенда показывает этот отказ, а не подменяет задачу.

Проверяющий рассчитан на JSON-объект с 1…128 парами целых координат в диапазоне ±10000. Булевы значения, дроби, повтор цели и неверные размеры отвергаются. Дополнительные поля не участвуют в доказательстве. Это проверка математического свидетельства, не криптографическая подпись и не универсальный безопасный загрузчик недоверенных гигантских файлов.

## Воспроизведение

```sh
python3 -S atlas/samples/transport/verify.py assets/transport/problem.json assets/transport/certificate.json
python3 -S atlas/samples/transport/solve.py assets/transport/problem.json --output /tmp/certificate.json
python3 -S atlas/samples/transport/verify.py assets/transport/problem.json /tmp/certificate.json
python3 -m venv .venv
.venv/bin/pip install -r atlas/samples/transport/requirements.txt
.venv/bin/python atlas/samples/transport/generate.py
.venv/bin/python -m unittest discover -s tests -p test_transport.py -v
```

Решатель и проверяющий требуют только стандартную библиотеку. Pillow нужен лишь для GIF/PNG. ZIP содержит HTML, исходную задачу, сертификат, аудит, CSV и оба скрипта. Порядок ZIP и его даты фиксированы. Генерация проверяется побайтно в одном окружении; переносимость sin/cos между всеми платформами не обещается.

Семь тестов охватывают 70 маленьких задач до n=7 с полным перебором перестановок, нулевую матрицу с несколькими оптимумами, плохой жадный выбор, строгие входы, повреждение свидетельства, автономную проверку из распакованного ZIP без site-packages и повторную генерацию. Опциональный `check-browser.cjs` проверяет именно распакованный ZIP: сертификат/порчу, ползунок, анимацию, сброс, клавиатуру, мобильную ширину, canvas, отсутствие HTTP и JS-ошибок. Зависимости для него указаны в начале файла; минимальному Linux могут понадобиться системные библиотеки Chromium.

## Исследование GitHub: восемь README, три выбранных исходника

Точные SHA, URL и найденные пути записаны в [sources.json](samples/transport/sources.json). Это тематическая выборка, не восемь аудитов алгоритмов. Чужие реализации и данные не копировались и не запускались.

- **PythonOT/POT**: README различает точный и регуляризованный транспорт. В `ot/lp/_network_simplex.py` изучены постановка `emd` с заданными массами и `center_ot_dual`: сдвиг одного потенциала компенсируется противоположным сдвигом другого. Здесь массы равны, вместо общего дробного плана нужна перестановка.
- **scipy/scipy**: README — общий обзор научного пакета. По дереву найден `rectangular_lsap.cpp`, но его исходник не изучался; алгоритм SciPy здесь не воспроизводится.
- **benchaplin/hungarian-algorithm**: README описывает min/max matching и O(n³); дополняет отсутствующие рёбра нулевым весом. Это не эквивалент запрету рёбер; наша задача — полная квадратная матрица без запретов.
- **bmc/munkres**: кроме README просмотрены `compute` и шаг изменения покрытых строк/непокрытых столбцов `__step6` в `munkres.py`. Здесь не копируется звёздочно-штриховой вариант; реализовано увеличение назначения с явными потенциалами для сертификата.
- **JuliaOptimalTransport/OptimalTransport.jl**: README показывает Sinkhorn и взвешенные выборки разных размеров. Регуляризованный дробный coupling не подменяет точное взаимно-однозначное назначение.
- **jeanfeydy/geomloss**: текущий README преимущественно содержит инструкции упаковки и релиза. Это лишь просмотр, не основание приписывать ему прочитанный алгоритм.
- **networkx/networkx**: README общего графового инструментария; исходники matching не изучались.
- **google/or-tools**: README и пример `assignment_linear_sum_assignment.py`: явные стоимости дуг, `SimpleLinearSumAssignment`, статусы OPTIMAL/INFEASIBLE/POSSIBLE_OVERFLOW. Нам нужен не только статус решателя, но переносимое независимо проверяемое свидетельство, поэтому библиотека не добавлена.

Итог исследования — не ещё один внешний виджет, а переносимый «ответ вместе с доказательством»: GitHub показывает движение, а скачанный маленький пакет позволяет проверить оптимальность без доверия к решателю.
