# Ссылки, которые раскрывают скрытый текст

**[Играть: «Сигнал потерян»](fragment-quest/README.md)** · [Граф маршрутов](../assets/fragment-quest/graph.json) · [Весь документ TXT](../assets/fragment-quest/play.txt)

## Что найдено

У браузера есть менее очевидное поведение: **переход к HTML-элементу внутри закрытого `details` раскрывает его предка**. Если секции объединены одинаковым `name`, раскрытие новой секции закрывает предыдущую.

По отдельности это fragment navigation и exclusive details. Вместе получается маленький **гипертекстовый автомат в одном Markdown-документе**, без скриптов. Нажимаешь действие → меняется hash адреса → открывается целевая сцена → предыдущая закрывается. В отличие от прежнего [конструктора](switchboard.md), здесь не 12 отдельных страниц. В отличие от [аккордеона](exclusive-panel.md), выбирать можно не только заголовок секции, но и действие из содержимого текущей.

Сама игра находится в отдельном `atlas/fragment-quest/README.md`; корневой README содержит вход в неё. Не выдаём ссылку из корневой галереи за встроенный игровой движок. Всё содержимое игры — **один** Markdown-файл, не внешний сайт.

## Собственный маленький квест

Семь сцен, четырнадцать направленных переходов и два сюжетных исхода: ответ маяка или эхо. Маршруты намеренно простые, названия сцен и подсказки открыты. В каждом узле есть действия, включая возврат. Нет ловушки, вынуждающей отправить Issue, и нет бессмысленной ссылки-кнопки без результата.

Это не настоящая радиосвязь и не симулятор инвентаря: выбор линзы не записывает найденный предмет. Позывной можно прочитать заранее, а любые сцены можно раскрыть вручную через summary. Это **гипертекстовый квест**, а не вычислительная игра с произвольными действиями, проверкой памяти или секретами.

История и тексты свои. Чужой ASCII-art, модели, фотографии и код игры не переносились. Новые картинки и анимации не добавлены: новый эффект — именно навигация с раскрытием содержимого.

## Неприятная, но важная зависимость от GitHub

GitHub Markdown API добавляет к авторским HTML id префикс `user-content-`, но оставляет ссылки-фрагменты как написано. Поэтому ссылки в этом конкретном документе явно указывают на **итоговые prefixed id**. Это проверено на ответе API с `mode: gfm` и `context: overbaffe1/gitEdit`.

Следствия:

- Такой документ **не универсален для любого Markdown-viewer**. На рендерере без того же преобразования id ссылки потребуют правки.
- Нельзя утверждать, что префикс — вечный публичный API. Он может измениться.
- Браузерная проверка ниже открывает HTML из официального API локально. Она **не запускает production CSS/JS самого github.com**. Обработчик ссылок на GitHub, расширения или другой клиент могут влиять на поведение.
- Поэтому каждое действие содержит номер и название целевой сцены. Если переход не раскрыл её, можно нажать нужный summary вручную.
- После ручного закрытия сцены повторный переход к уже текущему hash может не повторить раскрытие. Ссылки-самопереходы в граф не добавлены; ручной путь всегда остаётся.
- История браузера не объявлена надёжным игровым undo: восстановление scroll/open зависит от клиента. Для повторного прохождения есть явные действия возврата.

Не подменяем эти границы фразой «на GitHub точно работает во всех браузерах». Это полезный проверяемый приём с известной зависимостью, не новая гарантия платформы.

## Что проверено браузером

**Chromium 153.0.8010.0**, Playwright Core 1.65.1, две ширины: 1280 и 390 px. HTML взят реальным запросом к GitHub Markdown API **с контекстом репозитория**.

Для каждой ширины проверено:

- все **14 переходов**, не только счастливый путь;
- целевая сцена раскрывается, её текст виден, остальные шесть закрыты;
- hash совпадает с реальным целевым id;
- на все выборы приходится **одна загрузка документа**;
- ссылка активируется клавиатурой Enter;
- новая загрузка сразу с адресом закрытой финальной сцены раскрывает именно её;
- после закрытия всего содержимого можно вернуться к началу клавишей Пробел на summary;
- для прохождения не потребовался внешний сервис, загрузка изображения или runner.

390 px — узкий viewport Chromium, не тест физического телефона. Safari/Firefox и авторизованная страница github.com в этом проходе не проверялись. Браузерные бинарники и npm-зависимости лежат в исключённой `.local`, не в Git.

## Отдельное исправление прежнего видео-пробника

Предыдущий проход нашёл сохранение `video controls` в ответе Markdown API. Теперь проверили **одну и ту же строку** двумя запросами:

| Запрос | Результат 18 ноября 2026 |
|---|---|
| `mode: gfm`, без context | `<video>` сохранён |
| `mode: gfm`, `context: overbaffe1/gitEdit` | `<video>` удалён |

Это был **ложноположительный кандидат**, если переносить результат первого запроса на README репозитория. Наличие тега в одном API-режиме не доказывает возможность проиграть файл в другом. Новый браузерный скрипт повторяет этот контраст и не выдаёт его за готовый плеер. Ранее опубликованное наблюдение о сохранении тега следует читать с этим уточнением.

Квест, в отличие от этого видео-кандидата, проверен с repository context и реальными нажатиями. Ни видео, ни фиктивный URL вложения в README не добавлены.

## Повторить

```sh
python atlas/samples/fragment_quest/generate.py
python -m unittest discover -s tests -p test_fragment_quest.py -v
```

Стандартная библиотека Python. Генератор создаёт игровой README в подпапке, TXT, граф, фрагмент для корневого README и SHA-256; **корневой README не редактирует**. Все прежние байты корневого README сохранены отдельной проверкой.

Opt-in браузерный тест, Node 22+ и настроенный `gh`:

```sh
npm install --prefix .local/anchor-probe --no-audit --no-fund playwright-core@1.65.1 @sparticuz/chromium@153.0.0
node atlas/samples/fragment_quest/check-browser.cjs
```

Для минимального Linux с отсутствующими NSS/NSPR в этой сессии использованы локальные библиотеки из того же npm-пакета:

```sh
FRAGMENT_QUEST_BUNDLED_LIBS=1 node atlas/samples/fragment_quest/check-browser.cjs
```

Это локальная проверка, не запуск AWS, Codespaces или Actions. В README нет JavaScript, форм, Issue-ссылок и сетевого backend для ходов. TXT не копирует в clipboard автоматически: это обычный исходник.
