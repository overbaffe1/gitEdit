# Один шаг — один изменённый бит

Шестибитный **отражённый двоичный код Грея** (binary-reflected Gray code, BRGC): 64 позиции на кольце, 64 различных шестибитных слова. В отличие от обычной двоичной записи номера, у соседних позиций меняется **ровно один бит**, включая переход **63 → 0**.

## 31 → 32: зачем менять представление

Обычная запись: **011111 → 100000**. Меняются все шесть бит. Если каждый датчик уже выдал устойчивое старое или новое значение **своей дорожки**, то эти значения можно скомбинировать в любое шестибитное слово: **64 возможных чтения**. Например, младшие пять датчиков уже прочитали новое, старший ещё старое: получается `000000`, то есть **позиция 0**, хотя переход идёт между 31 и 32.

Код Грея для тех же позиций: **010000 → 110000**. Меняется только старший бит, остальные пять совпадают. Любая смесь старых и новых значений этих дорожек — либо `010000`, либо `110000`. После декодирования это только **31 или 32**.

Точно такой же бинарный худший случай есть на шве **63 → 0**: `111111 → 000000`. В нашем коде Грея это `100000 → 000000`, снова один изменяющийся бит. Кольцевые позиции и числовое значение кодового слова — разные вещи: `100000` здесь обозначает позицию **63**, а не 32.

## Строгая граница модели

Предполагаются **один соседний переход** и чтение каждой дорожки как её **устойчивого старого или нового бита**. Не предполагаются одинаковые задержки датчиков: источник каждого бита можно выбирать независимо. При этих условиях код Грея гарантирует только один из двух концов перехода.

Это **не** моделирование аналоговых сигналов, метастабильности, дребезга, несогласованных порогов, глитчей комбинаторной схемы, плохо совмещённых дорожек или слишком быстрого движения через несколько позиций. Если реальные показания не являются смесью двух соседних кодовых слов, доказательство неприменимо. Кодирование двоичного счётчика XOR-схемой само по себе не делает физические выходы безглитчевыми.

Это также **не исправляющий или обнаруживающий ошибки код**: все 64 шестибитных слова используются, контрольной избыточности нет. Контрпример в стенде: позиция 0 имеет `000000`; произвольно изменим бит с весом **16** — получим `010000`, декодируемое в **31**, далеко от обоих концов перехода 0 → 1. Это другая ситуация, не «новое значение своей дорожки» при данном переходе.

Количество возможных чтений не является их вероятностью. В переборе нет распределения задержек, частоты вращения или вероятностного шума.

## Формула и отражение

Конструктор использует `g(i) = i XOR (i >> 1)` для i=0…63. Обратное преобразование — накопительный XOR сдвигов слова: `g XOR (g>>1) XOR ...` до нуля. Эквивалентно, биты двоичного номера восстанавливаются префиксными XOR битов Грея от старшего к младшему.

Независимый проверяющий **не использует эту формулу** для подтверждения порядка. Он строит отражённый список рекурсивно:

1. Начать со списка из пустого слова.
2. К копии списка слева приписать 0.
3. К перевёрнутой копии слева приписать 1.
4. Соединить; повторить шесть раз.

Почему свойство сохраняется: внутри каждой половины соседние суффиксы отличаются одним битом по индукции; в месте соединения суффикс один и тот же, меняется только префикс. Первое и последнее слова также имеют одинаковые суффиксы и разные префиксы, поэтому цикл замыкается. Все слова различны: половины различаются первым битом, а суффиксы внутри половин уже различны. После шести шагов получаем все 2⁶ слова.

Это один стандартный порядок, не единственный возможный циклический код Грея. Вращения, другие ориентации и перестановки битов могут давать другие представления; наш сертификат сознательно фиксирует конкретный отражённый порядок и разрядность **6**, без заявления универсального API для произвольных больших целых.

## Все 64 перехода и все смеси

Для каждого из 64 переходов, включая шов, перебраны все **64 маски источника** шести дорожек: всего **4096** масок. Не каждая маска даёт отдельное слово: если дорожка не меняет значение, её старый/новый источник не влияет на результат.

При d изменяющихся битах число **различных** смесей равно 2^d. В обычном счётчике на кольце:

| Меняющихся битов | Переходов |
|---:|---:|
| 1 | 32 |
| 2 | 16 |
| 3 | 8 |
| 4 | 4 |
| 5 | 2 |
| 6 | 2 |

Сумма переключений — **126**, против **64** у Грея (ровно одно в каждом переходе). Это число логических изменений за полный обход, не измерение энергопотребления или электрических выбросов.

Если считать пары **(переход, различное прочитанное значение)**, то:

| Показатель | Обычный двоичный | Грей |
|---|---:|---:|
| Различных чтений, суммарно по переходам | **448** | **128** |
| Из них не являющихся концом своего перехода | **320** | **0** |

Эти суммы учитывают одно значение повторно в разных переходах. Они **не** утверждают наличие 448 разных шестибитных слов: глобально их только 64. Для каждого перехода два конца допустимы, поэтому 448−2×64=320 посторонних чтений обычного кода.

## Независимое свидетельство

Сертификат содержит список 64 слов и для каждого перехода — его начало/конец, отсортированные множества прочитанных **позиций** для двоичной и Gray-записи. `verify.py` не импортирует `model.py`:

- подтверждает список через рекурсивное отражение;
- заново вычисляет число различающихся символов, включая шов;
- перечисляет смешанные слова декартовым произведением старых/новых **строковых символов**;
- обычное слово читает в основании 2, Gray-слово ищет в независимо построенной таблице;
- требует точного совпадения множеств и только двух конечных позиций для каждого Gray-перехода.

Конструктор смесей работает с битовыми масками по изменяющимся разрядам, а тестовый оракул отдельно перебирает все 64 строковые маски источников каждого перехода. Проверяются 4096 вариантов источников, не 4096 уникальных кодовых слов.

Булевы/дробные индексы, повтор/потеря/неправильный порядок слов или чтений, неверный шов и постороннее значение отвергаются. Предел шести бит позволяет использовать JS-побитовые операции безопасно; сторонние обещания работы с произвольными целыми в наш код не переносятся. Это конечная математическая проверка, не защита JSON-сервиса от неограниченного ввода и не криптографическая подпись.

## Стенд и диск

Распаковать ZIP, открыть `gray.html` напрямую через `file://`. Сеть, сервер, CDN, веб-шрифты и fetch соседних файлов не нужны. Ползунок выбирает начало перехода 0…63; шесть кнопок задают, какой датчик взял старый/новый бит. Один набор масок применяется к обеим системам для наглядного сравнения. Если бит не меняется, переключение его источника может ничего не изменить — это ожидаемо.

В таблице всегда показаны старое/прочитанное/новое слова, а также декодированные позиции. Canvas их дублирует. Есть быстрые переходы 31→32 и 63→0, все старые/новые значения, полный аудит и отдельный контрпример произвольной ошибки. Кнопки и подписанный ползунок работают с клавиатуры. Автопроигрывания в HTML нет; GitHub README показывает только GIF или reduced-motion PNG и ссылку на пакет.

Печатать SVG на A4 в **100 %**. В отличие от безразмерного SVG, здесь явно заданы миллиметры: внешний диаметр рисунка **176 мм**, шесть дорожек по **10 мм**, радиусы от 28 до 88 мм. Чёрный сектор — 1, белый — 0. Читать **снаружи внутрь** от старшего бита к младшему, по середине сектора, не на границе. Позиция 0 — сверху, далее по часовой стрелке; подписи каждые восемь секторов. У сектора 0 центральный луч направлен ровно вверх, его границы расположены по обе стороны от него.

Диск — учебная схема, **не готовый оптический энкодер**. Печать, масштабы датчиков, выравнивание, пороги, механический люфт и синхронизацию не калибруем. SVG-тест подтверждает все 384 значения секторов/дорожек по метаданным; он не заменяет метрологический контроль физического отпечатка.

GIF показывает отдельный переход 31→32: датчики последовательно переключаются с младших дорожек к старшей. Это один иллюстративный порядок, не вероятностная модель задержек; полный аудит охватывает все маски, а не только показанную последовательность.

## Воспроизведение

```sh
# Только стандартная библиотека; также из распакованного ZIP:
python3 -S atlas/samples/gray/verify.py assets/gray/certificate.json
# Рисунки/анимация и тесты:
python3 -m venv .venv
.venv/bin/pip install -r atlas/samples/gray/requirements.txt
.venv/bin/python atlas/samples/gray/generate.py
.venv/bin/python -m unittest discover -s tests -p test_gray.py -v
```

Pillow **13.0.0** нужен для GIF/PNG. Рисунки, SVG-геометрия, код/UI собственные. Даты ZIP фиксированы; регенерация сравнивает все артефакты побайтно в одном окружении.

Восемь тестов: весь сертификат; отражение/обратное преобразование/контрпример; все 4096 масок; худшие переходы и суммы; порча; строгие входы; GIF/CSV/384 SVG-сектора/ZIP и standalone `-S`; регенерация.

`atlas/samples/gray/check-browser.cjs` проверяет ZIP в Chromium/file://: 64 JS-множества переходов совпадают с Python, все 4096 масок, шесть кнопок, ложную двоичную позицию 0 при переходе 31→32, оба конца Грея, шов, клавиатуру, контрпример ошибки, canvas, мобильную ширину, отсутствие HTTP и JS-ошибок. npm-зависимости указаны в начале скрипта; минимальному Linux нужны библиотеки Chromium.
