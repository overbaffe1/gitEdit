# Следующий поиск: клавиатура в README, Vega и Plotly

18 ноября 2026. **Исследование, не новый развёрнутый экспонат.** Корневой README, workflows и старые демонстрации не менялись.

## Необычная находка: клавиатура прямо в README

[veggiedefender/typing](https://github.com/veggiedefender/typing) показывает экран и нарисованную клавиатуру. Каждая клавиша — изображение внутри ссылки. Это выглядит существенно интереснее бейджей, но нужно разобраться, где выполняется действие.

Прочитаны README и три небольших файла Go: `main.go`, `handler.go`, `screen.go`. [Постоянные версии всех источников](samples/remote-readme-research/sources.json).

### Реальный путь одного нажатия

1. Читатель нажимает ссылку клавиши. Браузер уходит с GitHub на внешний `/type/<character>`.
2. Go-handler добавляет символ в объект `Screen`, общий для запросов в этом процессе.
3. Сервер отвечает **HTTP 302** обратно на адрес GitHub README.
4. Изображение экрана запрашивается через обычный URL и рисуется сервером из текущего буфера.
5. Для борьбы с кешем отдельная горутина раз в секунду отправляет `PURGE` на переданный при запуске Camo URL GitHub.

**Неожиданный нюанс:** имя `/screen.gif` вводит в заблуждение. В просмотренной версии handler отдаёт **`Content-Type: image/png`**, а `Screen.Render` вызывает **`png.Encode`**. Код двухкадрового GIF закомментирован. Это **не streaming GIF, не видеотрансляция и не push обновлений в уже загруженные пиксели**. По расширению URL нельзя определять действующий формат или архитектуру.

### Что ещё видно в исходниках

- Сервер хранит общий текст в памяти с mutex; отдельных пользовательских сессий в этих файлах нет.
- Enter преобразуется в пробел, backspace удаляет символ, длинный буфер сбрасывается при следующем добавлении после порога в 300 символов.
- У маршрута ввода есть IP rate limiter с параметром `5`; это не доказательство полноценной защиты от злоупотреблений.
- Изменяющий состояние handler используется через GET-ссылки. Предпросмотрщик ссылок или автоматический клиент потенциально может вызвать такой URL. Это вывод из устройства маршрута, а не выполненная атака.
- Нажатые символы логируются. Такую публичную клавиатуру нельзя использовать для паролей, приватных сообщений и других секретов.
- В `RenderHandler` указаны `Cache-Control: no-cache` и ETag. Это не гарантия немедленного обновления всех кешей и клиентов GitHub.
- Цикл PURGE не проверяет статус успешности ответа, не закрывает полученный response body и в просмотренной версии игнорирует ошибку `Do`. Наличие цикла в коде не доказывает, что кеш реально очищается сегодня.

Это обзор выбранных файлов, не полный security-аудит проекта. Сервис `kbd.jse.li` не открывался, кнопки не нажимались, чужой общий экран не менялся. **Работоспособность публичного экземпляра сейчас не подтверждена.**

### Можно ли повторить у нас?

Как отдельный **серверный эксперимент** — архитектурно да: картинка как экран, ссылки как команды, редирект обратно. Но это не новая нативная функция Markdown и не скрытый способ запускать JS в README.

Для ответственного варианта понадобятся:

- постоянно доступный публичный backend и понятные условия его эксплуатации;
- осознанное решение, общий это экран или персональное состояние;
- ограниченные безопасные действия, отсутствие приватного ввода и понятная политика логов;
- защита от автоматических переходов и спама; GET для изменения состояния — плохая отправная точка для чего-либо значимого;
- отдельная проверка того, как обновляется картинка **на реальном GitHub через Camo**;
- честная UX-подпись: команда временно открывает внешний сервер и возвращает на README, а не выполняется внутри Markdown.

Не стоит копировать ежесекундный PURGE как обязательную часть решения, обещать real-time или разворачивать чужой код с токенами. Здесь ни сервер, ни оплата, ни Actions не включались. Ни временный адрес preview, ни чужой live-screen не вставлены в наш README.

## Проверка Vega, Plotly и notebook

| Кандидат | Что прочитано | Что можно утверждать |
|---|---|---|
| Vega | README `vega/vega` | Vega действительно создаёт интерактивные визуализации Canvas/SVG, но README ведёт в отдельный Editor и на сайт примеров. Возможности библиотеки не равны возможностям GitHub README. |
| Plotly | README `plotly/plotly.py` | Описаны интерактивные графики в notebooks, standalone HTML и Dash; статический экспорт выделен отдельно. Вставка PNG из Plotly не становится интерактивным графиком. |
| Notebook на GitHub | Раздел Jupyter в `github/docs`, non-code files | Официальная документация прямо говорит о **static HTML** и о том, что custom JavaScript plots в репозитории не работают. Notebook не объявляем способом обойти ограничения README. |
| Нативные diagram fences | `github/docs`, Creating diagrams | Документированы четыре синтаксиса: Mermaid, GeoJSON, TopoJSON, ASCII STL. Vega/Plotly не перечислены. Это граница документированной поддержки, а не доказательство невозможности любой будущей или экспериментальной интеграции. |
| Bucket | README `vadimdemedes/bucket-app` | «Interactive readme» означает отдельное frontend-приложение на `onbucket.com`, где код можно редактировать и выполнять. Не плеер кода внутри github.com. Доступность сайта сегодня не проверялась. |
| GitHub markup | README `github/markup` | Конвертация разметки, sanitization и дополнительные GitHub-фильтры — разные этапы. Локальный HTML-export не доказывает, что тот же JS запустится на GitHub. |

В этом проходе не делались новые запросы Markdown API для Vega/Plotly и не запускался browser runtime: вывод ограничен документацией и просмотренными исходниками. Содержимое этих проектов не исполнялось, их зависимости не устанавливались.

## Итог для нашей галереи

**Действительно новый интересный кандидат найден:** README как интерфейс удалённого общего экрана. Но реальная интерактивность здесь принадлежит внешнему серверу, а не встроенному рендереру GitHub. Это иной класс решения, чем уже имеющиеся нативные STL, карты, аккордеон и fragment-квест.

Вместо очередного похожего стенда сохранены архитектура, ограничения и точные источники. Нового работающего remote-screen в репозитории нет. Исследование не исчерпывает все возможности GitHub и не означает, что редкие интерактивные приёмы больше не существуют.
