# Конструктор README из обычных Markdown-ссылок

[← Галерея](../README.md) · **[Открыть конструктор](switchboard/states/wide-ink-brief.md)**

## Что здесь можно попробовать

Выбрать ленту или плакат, одну из трёх палитр, короткий или подробный текст. Каждая ссылка ведёт на готовую страницу выбранного варианта. Предпросмотр и фрагмент для копирования соответствуют этому варианту.

Это **не новая встроенная функция GitHub и не JS-приложение**. Это небольшой конечный автомат на обычных Markdown-файлах: состояние хранится в имени файла, переход — обычная относительная ссылка. Вариант открывается как отдельный документ на GitHub, не меняет текущий README на месте. Переход требует загрузки страницы; «Назад» — обычная история браузера.

Практический результат — маленькая шапка README, которую действительно можно перенести в свой проект. Здесь нет нового правила головоломки, необходимости отправлять Issue, запускать Actions, входить в сторонний сервис или создавать codespace.

## Двенадцать состояний вместо сервера

| Ось | Варианты |
|---|---|
| Форма | `wide` — лента; `stack` — плакат |
| Цвет SVG | `ink` — чернила; `coral` — коралл; `forest` — лес |
| Текст | `brief` — коротко; `full` — подробнее |

Всего `2 × 3 × 2 = 12` страниц. Пример имени: `stack-forest-full.md`. При выборе другой палитры форма и объём текста сохраняются. Текущий выбор выделен жирным и галочкой — цвет не единственный индикатор.

Из каждого состояния есть **четыре перехода** к альтернативам: одна другая форма, две другие палитры и один другой объём текста. Итого **48 направленных переходов выбора**, не считая сброса и служебных ссылок. Любой вариант достижим из любого другого; разные параметры можно менять в любом порядке и прийти к одному результату. [Машиночитаемый граф](../assets/switchboard/states.json) содержит все состояния и переходы.

В тексте нет input, dropdown или вычисляемого фильтра. Выбор из готового набора — не произвольный ввод названия, не сохранение настроек в аккаунте и не отправка данных. GitHub и браузер, разумеется, видят обычные запросы страниц; это не обещание анонимного или офлайн-просмотра.

## Предпросмотр и перенос — не одно и то же

На странице варианта показан **отрендеренный Markdown-фрагмент**, а ниже тот же фрагмент как код. Изображение берётся из локальных файлов репозитория; для предпросмотра меняется только относительный путь к нему.

Для переноса в другой проект нужны два файла:

1. Сохранить выбранный SVG как `assets/readme-card.svg` в **своём** репозитории. Использовать Raw/Download, а не сохранить HTML-страницу GitHub под видом картинки.
2. Скопировать блок Markdown в **корневой** README. Заменить демонстрационное название и текст своими.

Фрагмент также доступен отдельным `.txt`. Ссылка на TXT не копирует в буфер обмена и не изменяет README автоматически. Исходный SVG — обычный текст, его можно редактировать. Надпись «НАЗВАНИЕ ПРОЕКТА» внутри SVG тоже нужно заменить вручную; изменение заголовка Markdown не переписывает картинку.

Вставка в README подпапки потребует поправить путь к картинке. Это не универсальный однострочный self-contained snippet: **один Markdown плюс один SVG**, что явно указано у результата.

## Что именно меняется

- Лента: SVG 1200×260, предпросмотр с шириной `100%`.
- Плакат: SVG 720×480, предпросмотр с ограничением ширины `520`.
- Цвет: три самостоятельные заливки/обводки в собственных SVG; не inline CSS, который GitHub может удалить.
- Текст: в полном варианте добавляются три шага и небольшая таблица с подсказками; короткий оставляет только заголовок и вводный абзац.

Это обложка-шаблон, а не настоящий статус проекта, график данных или чужой бренд. Палитра одинакова в светлой и тёмной теме намеренно; автоматическое переключение по системной теме здесь не обещается. Шрифты системные и могут немного отличаться. Изображения имеют alt, title/desc, а ссылки — текстовые названия. Нет скриптов, SVG-событий, анимации, внешних картинок и шрифтовых загрузок.

Новая иллюстрация здесь не является самоцелью: важен рабочий путь **выбор → новый документ → совпадающий предпросмотр → пригодный для переноса исходник**. Никаких нарисованных кнопок без ссылок.

## Что исследовано в других репозиториях

Прочитаны начальные части четырёх README, до 2500 символов, и относящиеся к ссылкам/изображениям разделы двух документов `github/docs`. [Постоянные SHA и URL](samples/switchboard/sources.json).

| Источник | Что выяснилось |
|---|---|
| `FVTC/choose-your-adventure` | README прямо описывает отдельный Markdown-файл на сцену и обычные относительные ссылки. Применён общий гипертекстовый принцип, но вместо истории — полезный выбор оформления. Сюжеты и файлы примера не скачивались. |
| `Srinivasa314/markdown-adventure` | Поиск описывал Markdown-adventure, но начало README уточнило: **нужен coding agent**, который придумывает сцену и сохраняет игру. Это не чистый GitHub-рендер; такой механизм не используется. Его инструкции не запускались. |
| `marcizhu/readme-chess` | README объясняет Python-бота, Workflows и отправку Issue для хода. Внешне выглядит игрой из README, но имеет серверную автоматику. Мы не переносим эту архитектуру и не создаём Issue на выбор цвета. |
| `rahuldkjain/github-profile-readme-generator` | Прочитанное начало ведёт на отдельный demo-сайт генератора. Здесь сознательно другой компромисс: только 12 заранее подготовленных вариантов, зато без отдельного приложения. Демо не запускалось. |
| GitHub: basic writing syntax | Относительные ссылки, изображения и показ исходника в code block — достаточные элементы для переходов и результата. |
| GitHub: permanent links | Ссылка с именем ветки со временем меняет содержимое; для фиксации версии можно использовать permalink. Имя состояния фиксирует выбор параметров, но не замораживает весь репозиторий. |

Это исследование README и документации, не аудит всего кода проектов. Чужие изображения, дизайн, тексты историй и реализации не копировались. Набор SVG, шаблоны и граф состояний собственные.

## Ограничения честно

- Переключатель **не встроен как изменяемая форма в текущий README**: ссылки открывают другие `.md`.
- Произвольных значений нет: только фиксированный набор параметров.
- Настройки не записываются в репозиторий/аккаунт; поделиться выбранным вариантом можно адресом страницы.
- Ничего не устанавливается и не запускается на runner; существующий ручной workflow проекта не изменён и не dispatch-ился.
- Публичный репозиторий обычно читается без аккаунта, но ограничения доступа, сеть и политика GitHub всё равно могут влиять на просмотр.
- Статическая проверка всех переходов и Markdown API не доказывают полное совпадение браузерной вёрстки с github.com.

## Воспроизведение

```sh
python atlas/samples/switchboard/generate.py
python -m unittest discover -s tests -p test_switchboard.py -v
```

Стандартная библиотека Python. Генератор создаёт 12 страниц, 12 TXT-фрагментов, 6 SVG, граф JSON и SHA-256, но **не редактирует корневой README**, workflows, шаблоны Issue и историю Git. [Генератор](samples/switchboard/generate.py) · [Контрольные суммы](../assets/switchboard/manifest.json).

Проверки проходят по всем 48 переходам, сверяют сохранение остальных параметров, достижимость и независимость порядка переключения, соответствие предпросмотра фрагменту, пути файлов, SVG и воспроизводимость. Весь прежний README сохраняется побайтово. Markdown API отдельно проверяется для всех 12 страниц, чтобы не ограничиваться стартовым вариантом.
