# Одинаковый спектр, разные карты

18 ноября 2026. Два разных спектра отражения могут дать один цвет. Теперь похожая ловушка в другом месте: **разные графы могут иметь один спектр матрицы**.

Это классическая пара: ладейный граф 4×4 и граф Shrikhande. Обе сети имеют 16 вершин, 48 рёбер, степень 6, одинаковые adjacency и combinatorial-Laplacian spectra. Но они **неизоморфны**: нельзя перенумеровать вершины так, чтобы совпали все связи.

Ни графы, ни сам математический факт не объявляются новым открытием. Свои здесь построение из определений, точный CSV-проверяющий, тепловой расчёт, изображения, анимация и автономное приложение.

## Две сети из коротких определений

Вершины нумеруются координатами `(x,y) ∈ Z₄×Z₄`, в CSV индекс `4x+y` лежит в **0…15**, на рисунке/в интерфейсе подписи **1…16**.

### Ладейный граф

Две разные вершины соединены, если находятся в одной строке **или** одном столбце доски 4×4. У каждой три соседа по строке и три по столбцу. Каждая строка и каждый столбец образуют полный граф на четырёх вершинах `K₄`: всего восемь.

### Shrikhande

Соединяем вершины, если разность координат по модулю 4 входит в:

```text
(1,0), (3,0), (0,1), (0,3), (1,1), (3,3)
```

То есть `±(1,0), ±(0,1), ±(1,1)`. Набор симметричен относительно смены знака, поэтому граф неориентированный. Каждая вершина снова имеет шесть соседей.

Это собственное построение известного Cayley graph, а не перенос edge dictionary из Sage. Сами классические определения и проверяемые свойства не становятся авторским открытием от новой картинки.

## Точное доказательство общего спектра

`A` — adjacency matrix, `I` — единичная, `J` — матрица из единиц. Для каждой матрицы целочисленно проверяется:

```text
A 1 = 6 1
A² = 4I + 2J
```

На диагонали `A²` равно 6: это степени. Вне диагонали равно 2: любые две разные вершины имеют ровно двух общих соседей. Это strongly regular parameters `(16,6,2,2)`.

На постоянном векторе собственное значение `A` равно 6. Оба графа связны, поэтому это значение простое. На ортогональном дополнении к постоянному вектору `J = 0`, значит `A² = 4I` и eigenvalues только `+2`/`−2`. Их кратности восстанавливаются из размерности 15 и `trace(A)=0`:

```text
spec(A) = 6 × 1, 2 × 6, −2 × 9
```

Каждая степень равна 6, поэтому `L = D − A = 6I − A`:

```text
spec(L) = 0 × 1, 4 × 6, 8 × 9
```

Это **combinatorial Laplacian**, не `I − D⁻¹/² A D⁻¹/²`. Для этой регулярной пары normalized spectrum получился бы делением на 6, но он не используется в опыте.

Дополнительно checker вычисляет оба characteristic polynomial по Newton identities с **Python integer arithmetic**. На каждом шаге делимость на порядок проверяется точно, eigen solver не вызывается:

```text
det(λI − A) = (λ−6)(λ−2)⁶(λ+2)⁹
det(λI − L) = λ(λ−4)⁶(λ−8)⁹
```

В JSON — полные коэффициенты в порядке убывания степени. Это второй путь проверки, а не список «одинаковых до шести знаков» floats.

## Почему карты всё-таки разные

Checker перебирает все `C(16,4) = 1820` четвёрки вершин каждого графа и проверяет наличие всех шести рёбер внутри каждой:

| Свойство | Ладейный | Shrikhande |
| --- | ---: | ---: |
| Вершин | 16 | 16 |
| Рёбер | 48 | 48 |
| Степени | все 6 | все 6 |
| Полных четвёрок K₄ | **8** | **0** |

Число K₄ сохраняется при любой перенумерации вершин. Разные числа доказывают неизоморфность: никакая смена рисунка/номеров не превращает один граф в другой. Это не перебор всех `16!` перестановок и не общий graph-isomorphism solver — здесь маленького инварианта достаточно.

На постере золотом выделен один K₄ ладейного графа: вершины 1–4 в человеческой нумерации. У Shrikhande отсутствие не выводится из внешнего вида: проверяются **все** четвёрки, даже если линий на рисунке много.

## Что делает «тепло»

Для единичной проводимости каждого ребра и единичной ёмкости каждого узла:

```text
u′(t) = −L u(t)
u(t) = exp(−tL) u(0)
```

Начальное состояние — единица в выбранной вершине, ноль в остальных. Это относительная математическая концентрация, не измерение температуры физического устройства. Масса `Σu` равна 1, значения неотрицательны.

Показывается **одна общая фиксированная шкала**: тёмный для 0, светлый для 1 с `sqrt(u)` только для видимости слабых значений. Это нелинейная цветовая карта, не изменение численных данных и не нормировка на максимум текущего кадра.

### Тепловой след — не сумма тепла

```text
H(t) = trace(exp(−tL))
     = Σ_i exp(−t λ_i)
     = 1 + 6 exp(−4t) + 9 exp(−8t)
```

`H` — сумма диагональных элементов kernel, то есть сумма вероятностей возврата по **всем возможным источникам**. Это не `Σu` одного запуска; последняя всегда 1. При `t=0` след 16, при больших временах стремится к 1 для связной сети.

Поскольку спектры совпадают, `H(t)` совпадает **для всех t**, не только на кадрах GIF. Смена выбранного источника меняет рисунок локального тепла, но не trace — так и должно быть.

У этой strongly regular пары даже отдельная диагональная return probability одинакова во всех вершинах, а сортированные значения point-source heat vector совпадают: один источник, шесть соседей, девять несоседей. **Нельзя обещать, что любую такую пару различит один скалярный тепловой датчик.** Связи при этом различны, и полные labelled kernel matrices не одинаковы. Их точное знание — намного больше информации, чем один eigenvalue list или trace.

### Как рассчитана экспонента

Приложение не проигрывает заранее посчитанные heat frames и не подставляет формулу следа вместо расчёта. В Python и JS используется uniformization:

```text
r = максимальная степень
P = I − L/r
exp(−tL) = exp(−rt) Σ_{k=0}^∞ (rt)^k/k! P^k
```

`P` — симметричная stochastic matrix (для удалённого ребра появляются self-loops этой **вспомогательной цепи**, не новые рёбра исходного графа). Для изолированного пустого графа обработан отдельный identity case.

Суммируются `k=0…96`. В интерфейсе `t ≤ 2`, `r ≤ 6`, то есть `rt ≤ 12`. Хвост точного ряда после 96-го слагаемого ограничен сверху примерно `3,49 × 10⁻⁵³`: первый отброшенный Poisson term при `μ=12` делится на `1−12/98`. **Это bound усечения ряда, не точность floating-point реализации**; на практике ошибки округления около 10⁻¹⁵ значительно больше.

В тестах uniformization сверяется с двумя независимыми путями: NumPy symmetric eigendecomposition и closed-form spectral projectors для исходной strongly regular пары. Проверяются также semigroup property, mass и nonnegativity. SciPy для этого не нужен.

## Контроль: удалить одно ребро

Кнопка удаляет ребро 1–2 (в CSV индексы 0–1) **только у Shrikhande**. Получаем 47 рёбер и степени 5/6. Равенство `A² = 4I + 2J` больше не выполняется, characteristic polynomials меняются.

При `t = 0,25`:

| Граф | Heat trace |
| --- | ---: |
| Ладейный исходный | 4,425294196158167 |
| Shrikhande исходный | 4,425294196158167 |
| Shrikhande без ребра 1–2 | 4,549653348064920 |

После удаления **заново** строятся степени, `L`, stochastic transition и matrix exponential. Формула `1+6e⁻⁴ᵗ+9e⁻⁸ᵗ` к изменённому графу не применяется. Интерфейс явно снимает утверждение о совпадающем спектре; он не выдаёт старые eigenvalues за новые.

На `t=0` traces всё ещё равны 16 — удаление ребра не меняет число вершин. Поэтому контроль показывается при положительном времени. Reset возвращает обе исходные CSV-матрицы и исходный режим.

## Живой опыт

[bench.zip](../assets/twins/bench.zip) содержит один `bench.html`, работающий после распаковки без сервера/сети. В нём только две adjacency matrices, декоративные координаты, UI, собственный heat solver и проверка small integer invariants.

- Slider времени 0…2, шаг 0,01.
- Выбор одного из 16 источников, доступный с клавиатуры.
- Highlight K₄ слева.
- Удаление ребра справа и reset.
- Повторная проверка `A²` и всех 1820 четвёрок каждого графа по текущим матрицам.

JS-проверка использует маленькие точные целые для `A²`/K₄; **полные characteristic polynomials вычисляет Python checker**, не браузер. Не заявляется точная BigInt factorization из HTML. Полный спектр исходной пары следует из указанных identity/regularity/connectedness и отдельно проверен Python.

Нет картинок внутри HTML, external libraries, кадровых массивов, `requestAnimationFrame` и autoplay. Нет источника звука и физического эксперимента. Позиции разные намеренно, но не участвуют в матрице/расчёте; длина, пересечение линий или близость точек **не** создают связь/проводимость. Пересечения рёбер без кружка — не дополнительные вершины.

В README — GIF, reduced-motion PNG и обычные ссылки. GitHub Markdown не исполняет это приложение, его нужно открыть отдельно.

## Повторить

Точная проверка — только Python standard library. Достаточно одного CSV и `certify.py`:

```sh
python3 atlas/samples/twins/certify.py assets/twins/rook.csv
python3 atlas/samples/twins/certify.py assets/twins/shrikhande.csv \
  --output /tmp/shrikhande-certificate.json
```

Checker поддерживает маленькие простые неориентированные бинарные матрицы до 32 вершин, намеренно без weighted/directed edges, loops и универсального graph-file import. Это ограничение формата/ресурсов, не научное ограничение характеристических многочленов.

Генератору нужны NumPy/Pillow:

```sh
python3 -m venv .venv
.venv/bin/pip install -r atlas/samples/twins/requirements.txt
.venv/bin/python atlas/samples/twins/generate.py --output /tmp/twins
```

Генератор не меняет README и не делает сетевых запросов. Даты ZIP фиксированы. Артефакты побайтово воспроизводятся в закреплённом окружении. Предопределены только классические графы и сценарий демонстрации, а не ответы decoder/checker.

## Чего опыт не утверждает

Нет двух физических барабанов, акустической записи или решения inverse geometry для непрерывной мембраны. Граф — конечная топология, а не геометрический домен PDE. Совпадают спектры конкретных матриц, не все возможные характеристики сети. Графы известны давно; найденный контрпример не заявляется новым математическим результатом.

**Для README:** вместо красивой «подписи графа» показать, почему подпись теряет информацию — и рядом положить короткое проверяемое доказательство, что объекты всё-таки разные.
