# Пиксельный код: изображение, которое является программой

18 ноября 2026. Ещё один необычный экспонат — **исходный код в цветных пикселях**, а не текст, зашифрованный внутри метаданных PNG. Своя небольшая программа на Piet вычисляет три числа, выводит `GIT` и естественно завершается.

На GitHub изображение остаётся изображением. Браузер не начинает исполнять Piet при открытии README; GIF показывает заранее рассчитанную трассу. Чтобы реально выполнить программу, скачай исходный PNG и запусти отдельный интерпретатор.

## Два вида картинки, которые нельзя перепутать

| Файл | Что это | Можно исполнять? |
| --- | --- | --- |
| `program.png`, 22 × 14 | Чистый исходник, 1 пиксель = 1 codel | Да, codel size = 1 |
| `program-24x.png`, 528 × 336 | Тот же исходник с nearest-neighbor масштабом ×24 | Да, с codel size = 24 |
| `execution.gif` | Анимация реальной трассы, с обводкой, командами и стеком | Нет, это объясняющее превью |
| `poster.png` | Неподвижный финальный кадр с объяснениями | Нет, это плакат |
| `trace.csv` / `trace.json` | Записанное поведение при исполнении PNG | Не заменяет исходный PNG |

Исходный PNG содержит только стандартные цветные пиксели и чёрные стены. В нём нет текста `GIT` в PNG-метаданных или альфа-канале. Вывод получается из арифметики стека. Открытие увеличенного файла и выполнение файла — разные действия; ссылка в README не пытается исполнять код в браузере.

## Как цвета становятся командами

У Piet шесть цветовых тонов — красный, жёлтый, зелёный, голубой, синий, пурпурный — и три уровня светлоты. Значение команды определяется **разностью** тона и светлоты при переходе между связными блоками. Один и тот же цвет не означает одну фиксированную команду.

В программе используются только:

| Команда | Δ тона | Δ светлоты | Действие |
| --- | ---: | ---: | --- |
| `push` | 0 | 1 | Кладёт в стек площадь покидаемого блока в codel |
| `pop` | 0 | 2 | Снимает верхнее значение; на пустом стеке ничего не делает |
| `add` | 1 | 0 | Складывает два верхних значения |
| `multiply` | 1 | 2 | Перемножает два верхних значения |
| `pointer` | 3 | 1 | Поворачивает направление DP по значению со стека |
| `outchar` | 5 | 2 | Выводит символ по числовому коду и снимает его со стека |

Начальное направление — вправо, CC — влево относительно DP. Высота цветных столбиков задаёт площади для `push`; лента проходит по их верхнему краю. Затем:

```text
7 × 10 + 1 = 71 → G
8 ×  9 + 1 = 73 → I
7 × 12     = 84 → T
```

Последний `push 1` и `pointer` поворачивают движение вниз. Два `pop` на пустом стеке служат нейтральными для стека переходами к конечному квадрату; они не являются несуществующей командой `halt` языка.

### Почему конечный квадрат не выпускает обратно

Последний блок имеет размер **5 × 5**, площадь **25 codel**. Вход находится в середине его верхней стороны. Для каждой комбинации направления DP и стороны CC выбирается один из **крайних углов**, а не середина входной грани. За всеми этими выбранными выходами — чёрное поле.

Исполнитель поочерёдно меняет CC и поворачивает DP; после **восьми неудачных попыток** программа завершена. Дойти до окончания заранее заданного списка команд недостаточно: этот факт проверяется на геометрии PNG. У анимации нет скрытого таймера, который выдаётся за остановку программы.

## Свой runner — маленький и честно ограниченный

[runner.py](samples/pixelcode/runner.py) загружает PNG, выделяет связные области по четырём соседям, находит выход по DP/CC, вычисляет команду из цветов и выполняет её над стеком. Он **не читает PLAN генератора, CSV или trace.json**.

Это учебный исполнитель **данного подмножества Piet, не полноценная реализация всего языка**:

- поддерживаются шесть перечисленных команд;
- цветные блоки и чёрные стены; белые проходы не поддерживаются;
- нет ввода, roll, switch, деления и остальных команд;
- неизвестные цвета, альфа-прозрачность, неоднородные увеличенные codel и неподдерживаемые команды — явные ошибки;
- лимит шагов защищает от бесконечного исполнения переходов; если достигнут, код завершения CLI — 2, а не ложное сообщение об успешной остановке;
- это не защищённая песочница для произвольных файлов: остаются обычные ограничения памяти/размера изображений и используемой библиотеки.

Для полного Piet используй отдельный полноценный интерпретатор, предварительно проверив его зависимости и поведение. Утверждение о совместимости здесь относится к нашему конкретному PNG.

## Независимая проверка: не только свой генератор проверяет себя

Для проверки был временно скачан JS-исполнитель **Bubbler-4/piet** на коммите `b6acb9aed431f2f1d39a9867cc46046bb4a9e05d`. Его `src/piet.js` задаёт свою каноническую палитру, `src/piet-run.js` — свою механику исполнения. `pngjs` независимо декодирует экспортированный PNG; цветовые значения передаются внешнему исполнителю через **его собственную таблицу цветов**, не через таблицу нашего runner.

Результат:

```text
stdout: GIT
finished: true
stack: []
step() calls: 29
```

У собственного исполнителя **20 успешных переходов** плюс отдельная запись об остановке. Внешний считает заблокированные попытки и завершение отдельными вызовами `step()`: поэтому 29 и 20 не противоречат друг другу.

[check-external.cjs](samples/pixelcode/check-external.cjs) воспроизводит эту опциональную проверку. Он требует **явного `--allow-download`**, скачивает закреплённый чужой JS во временный каталог, исполняет его и удаляет временные файлы. Вендоринга чужого кода и скрытых сетевых вызовов в генераторе или обычных тестах нет.

```sh
npm install --prefix /tmp/piet-tools pngjs
NODE_PATH=/tmp/piet-tools/node_modules \
  node atlas/samples/pixelcode/check-external.cjs --allow-download
```

Нужны Node, `gh` и доступ к GitHub. Запускается сторонний код: просмотри источники перед выполнением. Опциональный helper не нужен ни для просмотра картинки, ни для собственного runner.

## Запустить и перепечатать

```sh
python3 -m venv .venv
.venv/bin/pip install -r atlas/samples/pixelcode/requirements.txt
.venv/bin/python atlas/samples/pixelcode/runner.py assets/pixelcode/program.png
# stdout: GIT (без перевода строки)
.venv/bin/python atlas/samples/pixelcode/runner.py \
  assets/pixelcode/program-24x.png --codel-size 24
.venv/bin/python atlas/samples/pixelcode/runner.py \
  assets/pixelcode/program.png --trace /tmp/piet-trace.json
.venv/bin/python atlas/samples/pixelcode/generate.py
```

[Генератор](samples/pixelcode/generate.py) использует только Pillow и стандартную библиотеку. Сначала пишет PNG, затем открывает его исполнителем; все кадры построены из этой трассы. `--output /tmp/pixelcode` перепечатывает комплект отдельно. Корневой README не изменяется, сетевых запросов при генерации нет.

Не сохраняй исходник в JPEG и не применяй сглаживание, цветовые фильтры или произвольное масштабирование. Они меняют команды или площади блоков. Увеличение nearest-neighbor сохраняет геометрию **только при соответствующем параметре codel size**; если считать каждый из увеличенных пикселей отдельным codel, числа `push` изменятся.

Для README полезна сама идея: **не просто показать результат алгоритма, а дать изображение, которое является входом исполняющей системы**. Но обычная текстовая версия объяснения и отдельный исходник обязательны — цветовое зрение, анимация и установка интерпретатора не должны быть условием понимания проекта.

## Проверка выпуска

- **133 unittest-теста прошли**, без пропусков. Восемь новых тестов проверяют отдельный запуск PNG без генератора/трассы, реальные арифметические значения, изменение вывода при мутации пикселя, остановку через восемь геометрических блокировок, DP/CC, codel size, ошибки неподдерживаемых входов, reduced-motion-постер, реестр и побайтную перепечатку.
- Временный запуск независимого закреплённого JS-исполнителя через `pngjs` подтвердил `GIT`, пустой стек и завершение. Чужие файлы не добавлены в репозиторий.
