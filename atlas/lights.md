# Лампочки с двумя невидимыми печатями

Классический **Lights Out 5×5**: кнопка меняет состояние самой клетки и существующих соседей сверху, снизу, слева и справа. На краях нет переноса на противоположную сторону. Цель — всё погасить. Изменение одиночной лампы редактором **не является** разрешённым ходом.

На рисунке исходное поле погашается девятью нажатиями. Рядом та же раскладка, но одна угловая лампа изменена отдельно: её уже нельзя погасить никакой последовательностью разрешённых ходов.

## Девять вместо двадцати пяти

Исходное поле получено из полностью погашенного нажатием **всех 25 кнопок** по одному разу. Значит, известен очевидный способ вернуть его обратно: опять нажать все 25. Но это не минимум.

Все четыре маски решения имеют веса **9, 13, 13 и 25**. Минимум **9** подтверждается проверкой полноты этого набора, а не тем, что алгоритм просто нашёл короткий вариант. В данном примере минимальная маска единственна. Для произвольного решаемого поля минимальных масок может быть несколько; при равных весах выбирается меньшая целочисленная маска.

Дважды нажать одну кнопку — всё равно что не нажать её. Порядок кнопок не важен: изменения складываются XOR. Поэтому любой маршрут можно сократить до маски «нажать / не нажать каждую кнопку». Минимальное число отдельных нажатий равно минимальному числу единиц в подходящей маске. Разные порядки одних и тех же нажатий **не считаются** отдельными масками решения.

## Два узора, которые ходами не изменить

[Узоры-печати SVG](../assets/lights/seals.svg) выделяют два набора клеток. Для каждого считаем число включённых отмеченных ламп **по модулю 2**. При любом разрешённом нажатии эта чётность сохраняется: его крест пересекается с каждым узором в чётном числе клеток.

У погашенного поля обе чётности — 0. У исходного поля — **0 / 0**, у изменённого угла — **0 / 1**. Ненулевую печать ни один игровой ход не исправит. Редактор может менять класс чётностей, поэтому его действие отдельно обозначено и не увеличивает счётчик игровых нажатий.

Печати — не произвольная эвристика. Ниже проверяется, что они независимы и образуют **всё** пространство левых нулевых векторов матрицы ходов. Поэтому для этой конкретной игры условие «обе равны нулю» не только необходимо, но и достаточно для решения.

## Точная алгебра и независимая проверка

25 клеток нумеруются построчно, начиная с нуля. Бит i целого числа обозначает клетку i; младший бит — левый верхний угол. Матрица M имеет размер 25×25: столбец j — эффект нажатия j. Для текущего поля b нужно найти маску x, удовлетворяющую `M x = b` над **GF(2)**. Сложение — XOR, умножение — AND с суммированием по модулю 2; вещественное обращение матрицы здесь не подходит.

Собственный `core.py` строит матрицу геометрически и выполняет двоичное приведение строк. Сохраняются журнал обратимых операций, приведённая матрица R, преобразование L, позиции ведущих элементов, два базисных нулевых вектора и две печати.

Независимый `verify.py` **не импортирует** решатель и не запускает повторный поиск ведущих строк. Он:

1. Заново строит матрицу ходов из координат и граничных условий.
2. Воспроизводит **202** операции `swap(i,j)` и `row[i] ^= row[j]`. Индексы должны быть различны: XOR строки с собой необратим и запрещён. Каждая разрешённая операция обратима, поэтому ранг сохраняется.
3. Проверяет совпадение R и L с журналом, возрастающие ведущие позиции, единичные ведущие столбцы и нулевые строки только внизу. Это сертификат `R=L M`, где L обратима.
4. Получает **23 ведущих элемента**, значит ранг равен 23, размерность ядра — 2. Два свободных столбца дают независимый базис ядра; проверяющий восстанавливает его и проверяет `M k = 0`.
5. Берёт две строки L, соответствующие нулевым строкам R. Это независимые печати, поскольку строки обратимой L независимы. Дополнительно проверяет сохранение обеих печатей при всех 25 нажатиях: **50 проверок**.

Отсюда без перечисления всех полей следует:

- Всего полей: `2^25 = 33 554 432`.
- Достижимых из нулевого, то есть решаемых: `2^23 = 8 388 608` — **ровно четверть**.
- Четыре класса двух чётностей; игровые ходы сохраняют класс.
- У каждого решаемого поля ровно `2^2 = 4` маски решения.
- Разность XOR любых двух решений лежит в ядре: это «тихая» комбинация нажатий, не меняющая поле.

Для отдельного поля проверяющий принимает ещё свидетельство. Если печати ненулевые, оно подтверждает невозможность. Иначе требуется **четыре различных** корректных маски, каждая действительно должна гасить поле; размерность ядра доказывает, что других нет. Затем проверяются минимальный вес и выбранная маска. Проверяющий не решает систему для этого поля, а проверяет предъявленный полный набор.

Это проверка математического свидетельства для **фиксированного** ограниченного поля 5×5, не универсальный решатель произвольных размеров/узоров и не криптографическая подпись. Данные ограничены 25-битными целыми числами и журналом до 2000 операций. Булевы значения, дроби, выход за диапазон, необратимые/неизвестные операции, подменённые матрицы и неполный набор решений отвергаются. Это не универсальная защита JSON-парсера от гигантских недоверенных файлов.

## Что открыть

- [Анимация девяти нажатий GIF](../assets/lights/switches.gif), [начальное сравнение PNG](../assets/lights/proof.png). В README есть неподвижный вариант для reduced-motion.
- [Офлайн-стенд ZIP](../assets/lights/bench.zip): распаковать и открыть `lights.html` через `file://`. Сервер и сеть не нужны.
- [Матричный сертификат JSON](../assets/lights/certificate.json), [решаемое поле и все четыре маски](../assets/lights/solution.json), [невозможное поле](../assets/lights/impossible.json), [результат аудита](../assets/lights/audit.json), [маршрут JSON](../assets/lights/route.json).
- [Обе печати крупно SVG](../assets/lights/seals.svg).

В стенде можно играть кликом/касанием или активацией сфокусированной кнопки с клавиатуры, редактировать отдельные лампы, выделять печати, выбирать одну из четырёх масок и нажимать её первую отмеченную кнопку. После игрового хода выбранная маска сбрасывается к минимальной **для нового состояния**. Подпись «минимум» не меняет смысла, даже если для просмотра выбрана длинная маска. У нерешаемого поля решения не выдумываются, кнопка следующего нажатия выключена. После полного погашения минимум 0, но остаются три ненулевые тихие маски, возвращающие это поле к самому себе.

Кнопка «Изменить одну лампу» меняет левый верхний бит текущего поля, а не выполняет крестовое нажатие; в демонстрационном состоянии она создаёт невозможный двойник. Она не обязана исправлять любой из четырёх классов в нулевой. «Погасить редактором» задаёт нулевое исходное состояние и не выдаётся за решение игры. Кнопки загрузки сбрасывают счётчик ходов; режим редактора остаётся выбранным пользователем.

HTML автономен: сертификат встроен, внешних картинок, шрифтов, CDN, fetch и автопроигрывания нет. Браузер воспроизводит матричный журнал, проверяет приведённый вид, ядро и обе печати; отдельные тесты сравнивают его решения с Python. GitHub README JavaScript не исполняет — там анимация и ссылка на пакет.

## Воспроизведение

```sh
# Только стандартная библиотека; также работает из распакованного ZIP:
python3 -S atlas/samples/lights/verify.py assets/lights/certificate.json assets/lights/solution.json
python3 -S atlas/samples/lights/verify.py assets/lights/certificate.json assets/lights/impossible.json
# Отрисовка и тесты:
python3 -m venv .venv
.venv/bin/pip install -r atlas/samples/lights/requirements.txt
.venv/bin/python atlas/samples/lights/generate.py
.venv/bin/python -m unittest discover -s tests -p test_lights.py -v
```

Pillow 13.0.0 требуется только для GIF/PNG; рисунки, код и геометрия свои. ZIP имеет фиксированные даты, повторная генерация сравнивается побайтно в одном окружении.

Восемь тестов: полный матричный сертификат; **124 поля** против независимого алгоритма «перебрать 32 варианта первой строки и гасить сверху вниз»; сохранение печатей и двойное нажатие; ядро/точный минимум/невозможный двойник; порча сертификата и масок; строгие входы; GIF/маршрут/проверка распакованного ZIP без site-packages; повторная генерация. Метод первой строки не использует ни гауссов журнал, ни его базис, и независимо получает **все** решения тестируемых полей. Все 2²⁵ полей не перебирались: глобальные числа доказаны рангом.

Опциональный `check-browser.cjs` проверяет распакованный пакет: матричный аудит, **128** детерминированных полей JS против Python, выбор всех четырёх масок, девять шагов до нуля, отказ на невозможном поле, сохранение печатей после игрового хода, редактор, клавиатуру/двойное нажатие, выделение узора, canvas, мобильную ширину и отсутствие HTTP/JS-ошибок. npm-зависимости указаны в начале скрипта; минимальному Linux нужны библиотеки Chromium.
