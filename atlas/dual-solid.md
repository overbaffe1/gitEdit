## Что здесь нового, а что нет

Новая нативная функция GitHub в этом проходе **не найдена**. Вместо ещё одного одинакового интерактивного виджета найден сильный приём оформления: **трёхмерная амбиграмма**. Один объём имеет разные читаемые силуэты с двух направлений. Это не GIF, две сменяющиеся картинки или надпись-текстура на разных гранях куба.

Используется уже имеющийся STL-viewer GitHub. Поэтому новизна здесь **в двухликой скульптуре и действии читателя**, а не в обещании неизвестного движка. Внутри отдельного Markdown-README вставлен настоящий ASCII STL. Корневая галерея содержит вход и не раздувается ещё одним полным набором треугольников.

Модель собственная: с выбранного направления проекция читается **AI**, с перпендикулярного — **3D**. Читатель поворачивает её вручную. Дополнительный сайт, внешний backend, Actions, CadQuery, OpenSCAD и приложение для просмотра не требуются. Сам GitHub-viewer использует свой код и WebGL; отсутствие нашего JS не означает отсутствие JS у платформы.

## Как смотреть

1. Открыть [игровой с геометрией README](dual-solid/README.md) или сам STL.
2. Поворачивать модель, пока в одном боковом силуэте не получится **AI**.
3. Не переворачивая вертикаль, повернуть примерно на четверть оборота и найти **3D**.
4. Если читается зеркально, посмотреть с противоположной стороны. Если буквы рассыпаются на срезы, выровнять наклон.

Начальный ракурс GitHub не задаётся генератором. Скульптура не обязана быть читаемой из произвольного перспективного положения. **Точные гарантии ниже относятся к математическим ортографическим проекциям**, а не к любому ракурсу и освещению viewer. При недоступности WebGL те же силуэты доступны обычным SVG и бинарными строками JSON.

## Конструкция без тяжёлой CAD-библиотеки

Использован собственный маленький шрифт из битовых клеток 3×5. Между символами — одна пустая колонка. Обе надписи получаются размером 7×5.

Пусть `A(y,x)` — маска AI, а `B(y,z)` — маска 3D. Воксель добавляется тогда и только тогда, когда:

```text
V(x,y,z) = A(y,x) AND B(y,z)
```

Это пересечение двух вытянутых силуэтов. Проекция на XY берёт логическое OR вдоль Z; проекция на ZY — OR вдоль X. **В каждой строке обеих масок есть хотя бы один закрашенный пиксель**. Поэтому при проецировании ни один требуемый пиксель второй маской не уничтожается.

Это условие важно: нельзя обещать, что произвольная пара слов или картинок всегда точно восстанавливается тем же приёмом. Если в одной маске строка полностью пуста, она сотрёт соответствующую строку объёма и второй проекции.

В STL записываются только внешние грани занятых клеток. Грани между двумя соседними вокселями удалены. Квадрат разбит на два треугольника с нормалью наружу; координаты целочисленные, ребро вокселя равно 2 условным единицам. Это не миллиметры и не производственный масштаб.

Получилось:

| Свойство | Значение |
|---|---:|
| Занятых вокселей | 83 |
| Треугольников | 632 |
| ASCII STL | 67 185 байт |
| Объём по ориентированным треугольникам | 664 условных кубических единицы |
| Компонент по соседству через грань | 8 |
| Рёбер с кратностью 2 | 932 |
| Рёбер с кратностью 4 | 8 |

## Почему это не готовый файл для печати

Восемь компонент по связности через грани и восемь рёбер с четырьмя прилегающими треугольниками — **не скрытая ошибка, объявленная manifold-моделью**. У воксельного пересечения бывают раздельные части и касания только по ребру. Мы публикуем именно экранную скульптуру, не гарантируем единую физическую деталь, водонепроницаемую 2-manifold сетку или корректный slicing.

Подставку, стержни и поддерживающие пластины намеренно не добавляли: они меняют силуэты и требуют отдельной инженерной проверки. Не отправляй этот STL в производство на основании слова «STL». У других просмотренных проектов отдельно решаются вопросы supports/оснований; их printability-обещания сюда не переносятся.

## Независимые проверки

Проверяется не только совпадение генератора со своим JSON:

- из **реально записанных STL-треугольников** восстанавливаются обе силуэтные маски тестом попадания центров клеток в проекции треугольников;
- отдельный расчёт подписанного объёма по треугольникам даёт `83 × 2³ = 664`;
- у каждого треугольника проверяются площадь, длина нормали и её направление;
- число граней сверяется с количеством соседств в исходной сетке;
- статистика не прячет кратности рёбер и число компонент;
- в отдельном README находится точно тот же STL, что в файле, а proof SVG построен из проекции общего множества вокселей;
- побайтово сохраняется весь прежний корневой README, генератор не меняет его и workflows.

Markdown API проверяет сохранение `stl` fence и полного payload с контекстом репозитория. **Сам WebGL-viewer на github.com и субъективная читаемость в его начальном ракурсе в этой сессии не проверялись.** API-проверка не подменяет браузерный рендер модели.
