# Один обмен — и выхода нет

Здесь «восьмёрка», то есть родственник пятнашек на **3×3**, а не полные пятнашки 4×4. Восемь различных фишек 1…8 и одна пустота 0. Разрешено только сдвинуть соседнюю по стороне фишку в пустоту. Каждый такой сдвиг стоит один ход. Цель фиксирована: `123 / 456 / 780`.

| Достижимая раскладка | После обмена 1 и 2 |
|---|---|
| `867 / 254 / 301` | `867 / 154 / 302` |
| Кратчайший путь: **31 ход** | Пути до цели **не существует** |

Обмен двух непустых фишек не является допустимым ходом. Кнопка стенда меняет исходную задачу, а не предлагает читерский шаг решения.

Собственную позицию вводить девятью цифрами без пробелов: каждую из 0…8 ровно один раз. Невозможную позицию можно двигать, но подсказка не притворяется, что решение существует. Число «до цели» — точный оптимум, а не манхэттенская эвристика; число сделанных ходов считается отдельно. Сброс/загрузка обнуляют только этот счётчик.

GitHub README не запускает JavaScript: там GIF и ссылка на пакет. Стенд не включает автопроигрывание, ход подсказки выполняется только по нажатию. При нескольких оптимальных следующих шагах выбирается первый по индексу клетки. Уникальность маршрута не заявляется.

## Откуда берётся «невозможно»

Выписываем фишки построчно без нуля. Инверсия — пара, где большее число идёт раньше меньшего. Горизонтальный сдвиг не меняет порядка непустых фишек. При вертикальном сдвиге на ширине 3 фишка проходит мимо двух других, поэтому число инверсий меняется на чётное число. Значит, **чётность инверсий сохраняется**.

У цели она чётная. У трудной позиции она тоже чётная; перестановка 1 и 2 делает её нечётной. Никакая последовательность разрешённых ходов не восстановит нужную чётность. Этот аргумент относится к нечётной ширине; для 4×4 понадобилось бы учитывать строку пустоты. В этом экспонате другая ширина не поддерживается.

Из 9! = 362 880 перестановок ровно 181 440 достижимы. Чётность даёт необходимое условие; полнота нашей таблицы и сертификат спуска устанавливают достаточность для **всех** чётных перестановок этой конкретной задачи. Максимальное расстояние — 31; на нём находятся ровно две позиции. Это максимум от заданной цели, не утверждение о числе ходов для другой задачи или другого размера.

## Решатель и независимый проверяющий

`core.py` строит собственный обратный BFS от цели. Таблица занимает **362 880 байт**: по одному байту на перестановку в лексикографическом порядке. Индекс вычисляется факториальным кодом Лемера, включая ноль. Значения 0…31 — расстояния, 255 — недостижимо. Порядок фиксирован, файл не содержит заголовка. В HTML встроена base64-копия, поэтому загрузка через `fetch` и доступ к соседним файлам не нужны.

`verify.py` **не импортирует** решатель, его функцию индексации или генератор соседей. Он не повторяет BFS:

1. Перечисляет все перестановки `itertools.permutations(range(9))` и сопоставляет им байты по порядку.
2. Проверяет у всех перестановок соответствие 255 нечётной чётности; единственный ноль должен быть целью.
3. Заново строит соседей геометрическими сдвигами пустоты. Для каждого достижимого состояния проверяет все рёбра: сосед не помечен недостижимым, `|d(s)-d(t)| ≤ 1`.
4. У каждого состояния с положительной меткой требует соседа с меткой на единицу меньше.

**Почему этого достаточно:** единичное ограничение на каждом ребре и нулевая метка цели дают нижнюю границу на длину любого пути. Спуск по меткам даёт допустимый путь ровно такой длины. Нижняя и верхняя границы совпадают, поэтому все метки точны. Отсутствие других нулей гарантирует завершение спуска именно в цели. Проверены 483 840 **направленных** переходов достижимой компоненты (241 920 неориентированных рёбер). Рёбра недостижимой компоненты не перебираются; их отделяет инвариант чётности.

Проверка O(V+E) после перечисления фиксированных девятиэлементных состояний, хранит всю таблицу в словаре; это конечный сертификат для 3×3, не масштабируемый метод для 4×4 и не криптографическая подпись. JSON-отчёт — удобная сводка результата, а не свидетельство, принимаемое на доверии: проверяющий читает и проверяет сам BIN. Сравнение отчёта и полного маршрута дополнительно выполняют тесты.

Браузер проверяет все 362 880 индексов, размер/диапазон таблицы, число достижимых, максимум и единственность нуля. Это **не** повторная проверка всех рёбер. Для полного доказательства нужно запустить Python-проверяющий; интерфейс явно разделяет эти уровни.

## Воспроизведение

```sh
# Только стандартная библиотека, также из распакованного ZIP:
python3 -S atlas/samples/puzzle/verify.py assets/puzzle/distances.bin
# Полная генерация, включая рисунки:
python3 -m venv .venv
.venv/bin/pip install -r atlas/samples/puzzle/requirements.txt
.venv/bin/python atlas/samples/puzzle/generate.py
.venv/bin/python -m unittest discover -s tests -p test_puzzle.py -v
```

Pillow 13.0.0 нужен только для отрисовки GIF/PNG. Все иллюстрации нарисованы нашим кодом, внешних изображений и шрифтов нет. Порядок соседей и даты ZIP фиксированы. Тест повторной генерации сравнивает все артефакты побайтно в одном окружении.

Восемь тестов: независимая полная проверка, все индексы и чётности, легальность и оптимальность каждого из 31 хода, отдельный поиск ближних слоёв до глубины 9, порча таблицы, строгие входы, контейнеры/автономный ZIP без site-packages, повторная генерация. Опциональный `check-browser.cjs` проверяет именно распакованный ZIP: все байты таблицы и все индексы JS, совпадение полного маршрута с Python, невозможную позицию и сохранение нечётности после хода, незаконный клик, клавиатуру, ввод/ошибки, сброс и мобильную ширину. Проверяются отсутствие HTTP-запросов и JS-ошибок. Отдельные npm-зависимости указаны в начале скрипта; минимальному Linux понадобятся библиотеки Chromium.
