# Браузерный рабочий стол GitHub

[← README](../README.md)

## Главный опыт: точка превращает репозиторий в редактор

**[Открыть официальный web-editor для gitEdit](https://github.dev/overbaffe1/gitEdit)**.

На странице репозитория или PR GitHub нажми <kbd>.</kbd>, когда фокус не находится в поле ввода. <kbd>&gt;</kbd> открывает редактор в новой вкладке. Можно также заменить домен `github.com` на `github.dev`. Это документированная возможность GitHub, не наш сайт и не новая иллюстрация.

**Нужен вход в GitHub.** Редактор — браузерная версия VS Code: дерево файлов, поиск, подсветка и Source Control. Репозиторий не нужно клонировать на свою машину; редактор использует GitHub Repositories extension и работает в браузерной среде. Он не является offline-приложением и обращается к сервисам GitHub.

## Безопасный маршрут без публикации

1. Открой редактор по ссылке выше или клавишей `.`.
2. В дереве раскрой `atlas/samples/native_lab/generate.py`. Через **Go to File** можно найти файл по имени; конкретное сочетание клавиш зависит от платформы и keymap.
3. Найди `def mesh` и посмотри, как создаются вершины тора и октаэдра. Не нужно запускать код, чтобы читать его.
4. Открой `atlas/samples/contourpress/generate.py`, найди `def contours`: это другой настоящий генератор галереи, который сшивает сегменты.
5. Открой `atlas/samples/github_controls/generate.py`, найди `def links`: здесь собираются ссылки на нашу форму, в том числе URL-prefill.
6. Для опыта достаточно чтения. Не выбирай **Commit & Push**, переход в Codespaces или установку расширений.

В начало README добавлена таблица с обычным кодом, постоянным фрагментом и Blame для каждой остановки. [Маршрут JSON](../assets/browser-desk/tour.json) и [CSV](../assets/browser-desk/tour.csv) содержат те же сведения.

### Редактор бесплатный — но это не бесплатная виртуальная машина

| github.dev / VS Code для Web | Codespaces |
|---|---|
| Браузерный редактор, доступен бесплатно по документации | Вычислительное окружение с отдельными условиями квоты и оплаты |
| Нет связанной VM | Создаётся/возобновляется VM и devcontainer |
| Нет обычного интегрированного терминала, сборки и запуска Python | Можно запускать программу и использовать терминал |
| Только совместимые web-расширения | Более широкие возможности расширений |

В этом изменении **не создаётся codespace**, devcontainer, workflow или платный ресурс. Открытие ссылки на github.dev не обещает выполнить генераторы. Дополнительные сервисы, AI и произвольные расширения сюда не подключены. Если сам пользователь выберет переход в Codespaces или другой сервис, это уже отдельное действие с отдельными условиями.

### Приватность и черновики

Документация описывает хранение незакоммиченных правок в local storage браузера. Это не резервная копия: состояние может быть потеряно при очистке данных, смене браузера и других условиях. Но и закрытие вкладки не следует считать гарантированным удалением черновика.

Не вводи секреты, токены и личные данные ради опыта. Не включай Settings Sync и не устанавливай расширения без необходимости: это отдельные действия, которые могут добавлять обмен данными. Чтение файлов не требует публикации. Если использовать **Commit & Push**, изменения действительно отправляются в GitHub при наличии прав — это не имитация кнопки.

## Второй опыт: GitHub понимает символы кода

На обычной странице `.py` на github.com открой **Symbols**, если панель доступна, и выбери функцию. Нажатие на подходящее имя/вызов может показывать определение и ссылки на него. Это нативная code navigation на базе tree-sitter, а не наше всплывающее меню и не полнофункциональный Python language server.

Python присутствует в опубликованном списке поддерживаемых языков. Но навигация зависит от доступности индексации и текущего интерфейса; документация отдельно упоминает активные ветки и предел количества файлов. Поэтому в README:

- «Код» ведёт на **main**, где возможна навигация по активной ветке.
- «Точные строки» ведут на полный SHA и диапазон строк — это запасной путь без Symbols, фиксированный во времени.
- «Blame» ведёт к истории строк той же зафиксированной версии.

Не обещаем, что клик на любой идентификатор всегда определит правильный тип или покажет все динамические вызовы Python. AST-маршрут ниже тоже не решает эту задачу.

## Третий опыт: история прямо у строки

Открой **Blame** для одного из трёх файлов. GitHub группирует строки по коммитам: можно открыть соответствующий коммит и, если доступно, перейти к версии до изменения через **View blame prior to this change**.

Blame показывает историю изменения строк, а не доказывает авторство идеи или отсутствие копирования. В некоторых случаях перемещения, форматирование и merge-коммиты усложняют интерпретацию. Мы не переписываем историю, не скрываем коммиты через `.git-blame-ignore-revs` и не создаём фиктивных авторов.

На странице исходника:

- <kbd>y</kbd> меняет ссылку на ветку на постоянную ссылку с SHA;
- <kbd>b</kbd> открывает blame;
- <kbd>t</kbd> открывает поиск файлов;
- <kbd>?</kbd> показывает текущие горячие клавиши GitHub.

Не нажимай их в текстовом редакторе, ожидая такого же результата. Фокус, раскладка и настройки доступности могут влиять на срабатывание. Ориентируйся также на меню интерфейса.

## Что в этом изменении действительно проверяемо

Маршрут составлен **по существующему коду**, а не по специально нарисованным фиктивным функциям. Стандартный Python AST находит верхнеуровневые функции `mesh`, `contours`, `links`, их `lineno/end_lineno` и прямые вызовы по имени в том же файле. Это ограниченный синтаксический разбор: он не считает все ссылки по репозиторию, не разрешает алиасы/типы и ничего не исполняет.

Для каждого файла записаны полный SHA коммита, SHA-256 содержимого, диапазон строк, обычная ссылка, permalink и blame. Генератор читает рабочие файлы; тест отдельно сверяет их с содержимым зафиксированного коммита. Если исходник изменился, нельзя молча сдвинуть permalink: нужно обновить закреплённый ref и перепроверить маршрут.

**Не проверялись:** авторизованный интерфейс github.dev, фактическая готовность индекса Symbols, переключение Blame в удалённом браузере. Сетевые ограничения среды и отсутствие пользовательской браузерной сессии не позволяют честно утверждать обратное. Проверки URL/AST и прохождение Markdown API отделены от удалённого UI.

## Повторить

```sh
python atlas/samples/browser_desk/generate.py
python -m unittest discover -s tests -p test_browser_desk.py -v
```

Только стандартная библиотека Python. Генератор не изменяет README/исходники, не делает сетевых запросов, не создаёт коммитов и не запускает целевые модули. [Генератор](samples/browser_desk/generate.py) · [Закреплённый ref](samples/browser_desk/config.json) · [Контрольные суммы](../assets/browser-desk/manifest.json).

Для исторических проверок в shallow clone может потребоваться получить закреплённый коммит командой `git fetch origin <полный SHA> --depth=2`. Отсутствие истории помечается как skip с объяснением, а не подменяется доказательством совпадения.
