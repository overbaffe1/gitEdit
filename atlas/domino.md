# Две дырки — и мозаика невозможна

Полная шахматная доска **8×8**, из которой удалены **ровно две различные клетки**. Нужно покрыть остальные 62 клетки **31 домино 1×2**: только соседние по стороне клетки, без перекрытий, пропусков и выхода за границу. Поворот домино разрешён, диагональное соприкосновение не считается соседством.

Слева в анимации удалены A1 и G8: покрытие существует. Справа удалены A1 и H8: покрытие невозможно. Одна дырка сдвинулась на соседнюю клетку — изменился не результат случайной попытки укладки, а сама разрешимость.

Координаты используются как подписи картинки: **A1 — сверху слева**, H8 — снизу справа, строки идут вниз. Это не обещание стандартной ориентации настоящей шахматной позиции.

## Запрет по цвету

Каждое домино закрывает ровно одну тёмную и одну светлую клетку. Поэтому равенство числа цветов — необходимое условие любого полного покрытия.

- Удалены разные цвета: остаётся **31 тёмная и 31 светлая**.
- Удалены две тёмные: остаётся **30 тёмных и 32 светлых**.
- Удалены две светлые: остаётся **32 тёмных и 30 светлых**.

В последних двух случаях 31 домино не может покрыть доску: оно потребовало бы по 31 клетке каждого цвета. Неудачная укладка или исчерпанный лимит попыток не являются доказательством невозможности; цветовой дисбаланс — является.

## Почему разного цвета здесь достаточно

В произвольной вырезанной фигуре равенство цветов **не гарантирует** покрытия. Например, если оставить только две далеко расположенные клетки противоположных цветов, одно домино их не соединит. Наш результат относится именно к **двум удалённым клеткам полной доски 8×8**.

Предъявлен один замкнутый маршрут, проходящий через все 64 клетки ровно по одному разу и переходящий только через общую сторону: гамильтонов цикл. `cycle.json` хранит его явно, а проверяющий независимо подтверждает все 64 клетки и **64 соседства, включая замыкание**.

Цвета вдоль маршрута чередуются. Удалим две клетки противоположных цветов:

1. Два отрезка цикла между дырками превращаются в две непересекающиеся цепочки.
2. Расстояние по циклу между дырками нечётное, поэтому **каждая цепочка содержит чётное число оставшихся клеток**.
3. Попарно соединяем первую со второй, третью с четвёртой и так далее. Каждая пара соседствует по стороне, поскольку была ребром цикла.
4. Получаем ровно 31 домино, покрывающее все 62 клетки без пересечений.

При соседних по циклу дырках одна цепочка пуста: длина 0 тоже чётная, всё покрытие строится по другой цепочке длины 62. Если дырки одного цвета, обе цепочки нечётны; невозможность при этом доказывает общий цветовой аргумент, а не только неудача данного маршрута.

Таким образом, в этой конкретной задаче разные цвета — и необходимое, и достаточное условие. Алгоритм не ищет укладку и не перебирает её варианты: разрезает один заранее проверенный цикл. Построенное покрытие **не объявляется единственным, случайным или равномерно выбранным**.

## Все 2016 пар

Всего неупорядоченных пар дырок `C(64,2) = 2016`.

| Тип пары | Число | Результат |
|---|---:|---|
| Разные цвета | 32×32 = **1024** | Покрытие из 31 домино |
| Один цвет | 2×C(32,2) = **992** | Цветовой запрет |

Для каждой из 2016 пар построено свидетельство и проверено независимым кодом. Всего проверено **31 744 размещения домино** в 1024 покрытиях. Эти числа не означают подсчёт всех возможных укладок: это **по одному покрытию** для каждой разрешимой пары.

Дополнительно тесты решают **все 2016 случаев** другим алгоритмом — максимальным двудольным паросочетанием на графе соседних клеток. Он не использует наш цикл и не принимает решение только по равенству цветов: покрытие существует тогда, когда найдено 31 ребро паросочетания. Ответы полностью совпали. Это дополнительная программная проверка, а доказательство достаточности дано конструкцией цикла выше.

## Что именно проверяет независимый скрипт

`verify.py` не импортирует конструктор и не достраивает предъявленное покрытие.

Для разрешимого случая он требует 31 пару клеток, проверяет геометрическое соседство каждой пары и сравнивает весь список покрытых клеток с доской без дырок. Каждая оставшаяся клетка должна встретиться **ровно один раз**. Поэтому не пройдут диагональ, наложение, покрытая дырка, потерянная клетка или неполный набор домино.

Для невозможного случая он заново считает цвета оставшихся клеток, требует неравенства количеств и пустого списка домино. При равных цветах он **не принимает** заявление о невозможности. Для необязательного файла цикла отдельно проверяются уникальность всех 64 клеток и соседство каждой пары, включая последнюю с первой.

Формат ограничен двумя целыми различными индексами 0…63 и полной доской 8×8. Булевы значения не принимаются за числа, дроби/выход за границы и повтор одной дырки отвергаются. Индекс клетки — `8*строка + столбец`, с нуля; подписи на картинках — A1…H8. Это проверка конечных математических данных, не криптографическая подпись и не универсальная защита JSON-парсера от гигантских недоверенных файлов.

Один сертификат проверяется линейно по числу клеток/домино. Полная классификация перебирает все пары, **а не все укладки**. Ни заявлений о трудности общего случая, ни обобщения на произвольное число дырок здесь не требуется.

Печатать оба листа в **100 %**, без подгонки под страницу: клетка 20×20 мм, домино 20×40 мм. Вырезать внешние границы домино, **не** пунктирную линию между его половинами. Из доски выбрать и убрать любые две клетки. Бумажный набор — наглядное пособие; точность резки не является частью вычислительного доказательства.

В интерфейсе клик/касание или активация кнопки с клавиатуры удаляет/возвращает клетку. При третьем выборе заменяется самая ранняя дырка. Состояния с нулём или одной дыркой считаются **неполным вводом**, а не автоматически возможными/невозможными; проверка выключена до выбора ровно двух клеток.

Можно скрыть домино, чтобы рассмотреть шахматные цвета, или показать замкнутый маршрут. Отдельная кнопка повторяет все 2016 построений и проверок в браузере. HTML сам строит покрытие из встроенного цикла; не загружает готовые картинки покрытий, CDN, шрифты или соседние JSON через fetch. Автопроигрывания нет. GitHub README не исполняет JavaScript: там GIF и ссылка на пакет.

Анимация показывает последовательное появление домино в **уже построенном** покрытии, а не случайный поиск или доказательство невозможности через неудачные попытки.

## Воспроизведение

```sh
# Только стандартная библиотека; работает и из распакованного ZIP:
python3 -S atlas/samples/domino/verify.py assets/domino/possible.json --cycle assets/domino/cycle.json
python3 -S atlas/samples/domino/verify.py assets/domino/impossible.json --cycle assets/domino/cycle.json
# Отрисовка и тесты:
python3 -m venv .venv
.venv/bin/pip install -r atlas/samples/domino/requirements.txt
.venv/bin/python atlas/samples/domino/generate.py
.venv/bin/python -m unittest discover -s tests -p test_domino.py -v
```

Pillow 13.0.0 нужен только для GIF/PNG. Сеть, цикл, рисунки и печатные листы собственные. Даты ZIP фиксированы; все артефакты сравниваются при повторной генерации побайтно в одном окружении.

Восемь тестов: независимая проверка всех пар; отдельный максимальный matching для всех пар; сертификат цикла и чётности цепочек; соседние дырки/нулевая цепочка/порядок выбора; порча; строгие входы; GIF/SVG/CSV/автономный ZIP без site-packages; повторная генерация.

Опциональный `check-browser.cjs` проверяет распакованный ZIP: **все 2016 конструкций JS побайтно по числовым данным совпадают с Python**, полный итог 1024/992, цикл, 64 кнопки, выбор/возврат/замену третьей дырки, неполный ввод, нулевую цепочку, переключатели, клавиатуру, canvas, мобильную ширину и отсутствие HTTP/JS-ошибок. npm-зависимости указаны в начале скрипта; минимальному Linux нужны библиотеки Chromium.
