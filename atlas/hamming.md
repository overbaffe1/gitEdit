# Семь лампочек находят сломанную

Обычный двоичный код Хэмминга **(7,4)**: четыре бита данных, три контрольных бита, семь позиций. Гарантия: восстановить исходное слово, если изменилось **не более одного бита**. Это не расширенный код (8,4) SECDED и не универсальное исправление повреждений.

## Позиции, а не разряды числа

Позиции **1…7 идут слева направо** в напечатанной строке. Контрольные биты находятся в позициях **1, 2, 4**; данные, в исходном порядке, — в **3, 5, 6, 7**. Используется чётная чётность, то есть сумма каждой группы по модулю два должна быть нулём.

| Проверка | Позиции | Вес синдрома |
|---|---|---:|
| S1 | 1, 3, 5, 7 | 1 |
| S2 | 2, 3, 6, 7 | 2 |
| S4 | 4, 5, 6, 7 | 4 |

Для кодирования вставляем данные, затем выбираем каждый контрольный бит так, чтобы его группа стала чётной. Каждая группа содержит только свой контрольный бит, поэтому расчёты не мешают друг другу. Пример: `1011 → 0110011`.

Для принятой строки считаем три остатка S1, S2, S4 и читаем число **S4 S2 S1** в двоичной системе, то есть `S1 + 2*S2 + 4*S4`. Не путать порядок строк таблицы с порядком записи двоичного числа.

В неподвижном примере перевёрнута позиция 5: принято `0110111`, проверки **S1=1, S2=0, S4=1**. Синдром `101₂ = 5`. При условии не более одной ошибки нужно изменить позицию 5, получить исходное `0110011`, затем извлечь `1011`.

## Почему синдром указывает на одиночную ошибку

Двоичная запись номера каждой позиции определяет её участие в группах. Позиция 5 (`101₂`) участвует в S1 и S4, но не в S2; позиция 6 (`110₂`) — в S2 и S4.

У правильного кодового слова все проверки нулевые. Изменение одного бита меняет ровно те проверки, в которых он участвует. Все семь ненулевых трёхбитных столбцов различны, поэтому каждая одиночная ошибка имеет собственный синдром 1…7. Если синдром нулевой, при предположении **≤1 ошибки** ничего исправлять не надо.

Всего правильных слов 16: четыре независимых бита данных однозначно определяют три контрольных. Минимальное расстояние Хэмминга между различными словами равно **3**:

- Разность кодовых слов тоже проходит проверки.
- Один ненулевой бит имеет ненулевой синдром.
- Два различных ненулевых столбца не могут дать XOR=0, поэтому двухбитовая разность тоже не кодовое слово.
- Три позиции 3, 5, 6 имеют XOR `3 XOR 5 XOR 6 = 0`, значит существует трёхбитовая разность кодовых слов.

Следовательно, шары радиуса один вокруг кодовых слов не пересекаются. В каждом 8 строк: само слово и семь одиночных изменений. **16×8 = 128 = 2⁷**, поэтому эти шары покрывают все семибитные строки. У любой принятой строки есть ровно один ближайший кандидат на расстоянии ≤1. Это свойство кода, а не доказательство того, что именно этот кандидат был отправлен.

## Две ошибки: обнаружить — не значит исправить

При двух изменениях в позициях i и j синдром равен **i XOR j**. Для различных i и j он ненулевой: проверка обнаруживает, что принятое слово не является допустимым. Но он совпадает с синдромом одиночной ошибки в третьей позиции k=i XOR j. Декодер не может различить эти ситуации по принятой строке.

Наша демонстрация:

1. Отправлены данные `1011`, кодовое слово `0110011`.
2. Изменены позиции **3 и 5**, принято `0100111`.
3. Синдром `110₂ = 6`.
4. Обычный single-error-декодер меняет позицию 6: кандидат `0100101`.
5. Все проверки кандидата нулевые, но извлечённые данные — **`0101` вместо `1011`**.

Таким образом, обычный (7,4) **обнаруживает любую двойную ошибку при проверке принадлежности к коду**, но не умеет отличить её от одиночной и не обеспечивает одновременно SECDED. Автоматическое исправление по синдрому при двойной ошибке всегда создаёт другое допустимое слово. Отдельная восьмая общая чётность в расширенном (8,4) позволяет различать одиночную и двойную ошибки в соответствующей модели, но в нашем семибитном стенде её нет.

Три ошибки **3, 5, 6** сразу переводят исходное слово в тот же неправильный кандидат, синдром будет нулевым без каких-либо действий декодера. Поэтому фраза «все проверки прошли» не равнозначна «ошибок не было».

Стенд знает исходные данные и отправленную строку для сравнения. Настоящий приёмник получает только принятую строку: красный флаг «не совпало с отправленным» — знание **демонстрации**, а не способность семибитного декодера распознать все множественные ошибки. Это явно подписано в UI.

## Полный перебор: 2048 передач, а не вероятность

Для каждого из **16** четырёхбитных сообщений проверены все **128** масок изменения семи бит. Маска задаётся целым 0…127: бит 0 маски относится к позиции 1 строки, бит 6 — к позиции 7. Значения строк CSV читаются как текст с ведущими нулями.

| Число изменённых бит | Случаев | Восстановлено исходное | Нулевой синдром до декодирования |
|---:|---:|---:|---:|
| 0 | 16 | 16 | 16 |
| 1 | 112 | 112 | 0 |
| 2 | 336 | 0 | 0 |
| 3 | 560 | 0 | 112 |
| 4 | 560 | 0 | 112 |
| 5 | 336 | 0 | 0 |
| 6 | 112 | 0 | 0 |
| 7 | 16 | 0 | 16 |

Сумма — **2048** проверенных передач, **128** успешных исходов (16 чистых + 112 одиночных ошибок). Это классификация конечного пространства, **не вероятность восстановления в реальном канале**: маски не обязаны быть равновероятны. Здесь нет модели BSC, измерения BER, шума UART, заголовков, стираний, вставок, удаления битов, ошибок синхронизации или криптографической аутентификации. Есть только инверсии известных семи позиций.

## Независимое свидетельство

[Чистый случай](../assets/hamming/clean.json), [одна ошибка](../assets/hamming/single.json), [две ошибки](../assets/hamming/double.json), [необнаруженные три](../assets/hamming/undetected.json).

Сертификат хранит исходные четыре бита, отправленную и принятую строки, синдром, кандидата и извлечённые данные. `verify.py` **не импортирует codec.py** и не меняет указанный синдромом бит, чтобы выбрать кандидата. Вместо этого он независимо перечисляет все 128 семибитных строк, отбирает 16, удовлетворяющих явным группам чётности, и требует, чтобы предъявленный кандидат был **единственным** словом на расстоянии ≤1 от принятого. Также заново проверяет отправленное слово, исходные данные и синдром.

`verified: true` означает **корректно описан результат декодера**, а не «передача восстановлена». Поля `candidate_equals_sent` и `within_one_error_guarantee` отдельно указывают совпадение с отправленным и соблюдение модели. Поэтому свидетельство двойной ошибки законно проходит математическую проверку, но содержит `candidate_equals_sent: false`.

Входы — строки из 0/1 точной длины, синдром — целое 0…7, не булево значение. Чужой формат, потеря ведущих нулей, неверные строки/синдром/кодирование/данные/кандидат отвергаются. Это учебная проверка конечных данных, не криптографическая подпись и не защищённый от неограниченных файлов JSON-сервис.

## Использование

ZIP распаковать и открыть `hamming.html` напрямую через `file://`. Нет CDN, веб-шрифтов, fetch соседних файлов или сетевых запросов. Выбрать одно из 16 сообщений, переключать семь лампочек; отдельные кнопки задают чистый, одиночный и двойной случаи. Пересчитываются три чётности, синдром, кандидат и честное сравнение с отправленным. Кнопка полного аудита повторяет 2048 случаев и сравнивает декодирование с независимым перебором ближайших кодовых слов в браузере.

Canvas показывает участие позиций в группах, а текстовая таблица дублирует группы и результаты; лампочки — настоящие кнопки, переключаемые с клавиатуры. UI без автопроигрывания. GitHub README показывает GIF (или PNG при reduced-motion), но не исполняет HTML/JS: интерактивность находится в скачиваемом пакете.

Памятку SVG печатать на A4 в **100 %**. В пустых клетках можно написать отправленные/принятые биты и считать единицы по цветным группам. Позиции и формулы подписаны, цвет не является единственным носителем информации. Это бумажная памятка, не электронное устройство и не прибор проверки носителей.

Анимация последовательно показывает чистое слово, все семь одиночных ошибок, двойную ошибку, неверное «исправление» и тройное необнаруженное изменение. Она не утверждает, что все ошибки накапливаются в одном канале: кадры — отдельные подписанные примеры.

## Воспроизведение

```sh
# Только стандартная библиотека; также из распакованного ZIP:
python3 -S atlas/samples/hamming/verify.py assets/hamming/single.json
python3 -S atlas/samples/hamming/verify.py assets/hamming/double.json
# Изображения и тесты:
python3 -m venv .venv
.venv/bin/pip install -r atlas/samples/hamming/requirements.txt
.venv/bin/python atlas/samples/hamming/generate.py
.venv/bin/python -m unittest discover -s tests -p test_hamming.py -v
```

Pillow **13.0.0** нужен для рисунков. Схема, изображения, программы и UI собственные. ZIP имеет фиксированные даты; тест регенерации сравнивает все артефакты побайтно в одном окружении.

Восемь тестов: все 2048 передач независимым checker; кодовая книга/расстояние/разбиение всех 128 принятых строк на шары; синдромы всех одиночных и двойных ошибок; четыре примера; порча свидетельств; строгие входы; GIF/CSV/ZIP и standalone `-S`; повторная генерация.

`atlas/samples/hamming/check-browser.cjs` проверяет распакованный ZIP в Chromium/file://: **все 2048 JS-результатов точно совпадают с Python**, итоговый аудит по весам, 16 исходных сообщений, 7 кнопок, двойной контрпример, переключение и возврат бита клавиатурой, canvas, мобильную ширину, отсутствие HTTP и JS-ошибок. npm-зависимости указаны в начале скрипта; минимальному Linux нужны библиотеки Chromium.

Это просмотр описаний, не семь аудитов реализаций; три README почти пустые.
