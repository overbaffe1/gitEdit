# Лишняя дорога делает путь дольше

Парадокс Браесса: добавление дороги может ухудшить **равновесное** время поездки, даже если новая дорога имеет нулевую стоимость. Здесь показана классическая игрушечная сеть, не прогноз для реального города.

## Сеть и предположения

Четыре узла S, A, B, T; один источник и один сток. Разрешены только следующие **ориентированные** рёбра:

| Ребро | Время, минуты |
|---|---:|
| S→A | поток этого ребра / 100 |
| A→T | 45 |
| S→B | 45 |
| B→T | поток этого ребра / 100 |
| A→B, только после открытия | 0 |

Обратного ребра B→A нет. Без перемычки доступны SAT и SBT, с ней добавляется SABT. Нулевое время перемычки — идеализация, как и нулевое время переменного ребра при нулевом потоке. Q — общий спрос в условных единицах непрерывного потока. Это не число машин, одновременно нарисованных на схеме.

Используется **стационарное неатомарное равновесие Уордропа**: каждый используемый маршрут имеет минимальное время среди доступных. Неиспользуемый может быть дороже **или равен**. Участники бесконечно малы и не меняют поток при одиночном выборе. Это не конечная игра 4000 водителей, не динамика адаптации маршрутов, не модель очередей, светофоров, выбросов или пропускной способности реальных улиц.

## Свидетель при Q=4000

| Сеть | Поток SAT | Поток SBT | Поток SABT | Время используемых маршрутов |
|---|---:|---:|---:|---:|
| Перемычка закрыта | 2000 | 2000 | недоступен | 65 |
| Перемычка открыта | 0 | 0 | 4000 | 80 |

До открытия переменные рёбра несут по 2000: `20+45 = 45+20 = 65`.

После открытия весь поток идёт S→A→B→T: `40+0+40 = 80`. Старые SAT и SBT при **этих новых потоках** стоят `40+45 = 45+40 = 85`. Поэтому уходить с используемого маршрута бесконечно малому участнику невыгодно. Получено новое равновесие, но хуже прежнего: **+15 минут**, отношение времён **16/13**. Это сравнение двух равновесий разных сетей, **не** price of anarchy относительно общественного оптимума в одной сети.

При старом распределении новая перемычка сначала дала бы путь `20+0+20=40`. Но его стоимость не остаётся 40 после перераспределения всего потока. Анимация не изображает и не доказывает сходимость процесса такого перераспределения — она показывает два уже рассчитанных стационарных состояния.

## Когда эффект исчезает

Обозначим потоки трёх маршрутов x=SAT, y=SBT, z=SABT. Без перемычки `x=y=Q/2`, время `45+Q/200`.

С перемычкой точное равновесие имеет три режима:

| Спрос | x=y | z | Время используемых путей |
|---|---:|---:|---:|
| 0 < Q ≤ 4500 | 0 | Q | Q/50 |
| 4500 ≤ Q ≤ 9000 | Q−4500 | 9000−Q | 90 |
| Q ≥ 9000 | Q/2 | 0 | 45+Q/200 |

На границах соседние формулы совпадают. Равенство стоимостей использованных маршрутов в среднем режиме требует `(x+z)/100 = 45`, откуда переменные рёбра несут по 4500.

Сравнение с `45+Q/200` даёт:

- Q < 3000: перемычка помогает;
- Q = 3000: время одинаково;
- **3000 < Q < 9000: перемычка ухудшает время**;
- Q ≥ 9000: не влияет на равновесное время.

Это вывод для этой сети и этих функций, не общий закон дорожного строительства. Диспетчерский минимум суммарного времени здесь не рассчитывается. Если оптимизатору разрешено просто не использовать новую дорогу, добавление доступного ребра само по себе не может ухудшить достижимый общественный минимум: прежнее решение остаётся допустимым. Парадокс относится именно к самостоятельному выбору маршрутов.

Их количество, плотность и геометрическая скорость не служат измерением потока, времени, очереди или пропускной способности. В частности, нулевое расчётное время перемычки не кодируется временем прохождения её нарисованной длины. Числа на рёбрах и в таблицах вычислены из модели независимо от рисунка.

GitHub не исполняет JavaScript в README: там GIF, статичная альтернатива и ссылка на ZIP. HTML полностью автономен: график встроен как data URI, сертификаты — в документ; fetch, CDN и внешних шрифтов нет. Ничего не начинает двигаться автоматически в самом стенде.

## Что проверяется независимо

`model.py` использует кусочно заданные формулы равновесия с `fractions.Fraction`. Это собственная маленькая реализация для одной фиксированной сети, не общий решатель транспортного равновесия.

`verify.py` **не импортирует** этот решатель и не использует его кусочные формулы. Из сертификата он берёт только спрос, признак топологии, потоки и заявленные стоимости. Затем:

1. Проверяет неотрицательность потоков и сумму Q; ключи должны точно совпадать с доступными маршрутами.
2. По спискам рёбер маршрутов восстанавливает нагрузку каждого ребра. Этим автоматически обеспечивается сохранение потока в промежуточных узлах.
3. Заново вычисляет времена рёбер и всех доступных маршрутов.
4. Проверяет, что всякий маршрут с положительным потоком имеет минимальное время; используемые маршруты не дороже любых альтернатив.
5. Проверяет заявленные времена и выводит среднее время реально используемого потока.

Для нашей неатомарной модели это и есть условие равновесия Уордропа. Проверяющий не доказывает социальную оптимальность, уникальность всех разложений потока, сходимость обучения агентов или практическую пользу закрытия дороги. Он не доверяет полю с готовым результатом проверки.

Поддерживаются целый Q=1…10000, настоящий JSON boolean для топологии и ограниченные рациональные строки для потоков/стоимостей. Булевы числа вместо Q, дробный Q, NaN, нулевые знаменатели, отрицательные или несохраняющие спрос потоки отвергаются. Это проверка математических данных, не универсальная защита парсера от произвольно огромных недоверенных файлов.

Браузер отдельно восстанавливает условия для 182 опубликованных сертификатов. На сетке регулятора корректные стоимости целые или полуцелые и точно представимы JavaScript Number; это не заявка на общий точный рациональный решатель в JS. Кнопка порчи сохраняет суммарный спрос, но меняет потоки без пересчёта сертификата — проверка обнаруживает нарушение. Сдвиг ползунка или сброс восстанавливает исходные данные.

## Воспроизведение

```sh
# Стандартная библиотека; также работает из распакованного ZIP:
python3 -S atlas/samples/braess/verify.py assets/braess/closed.json
python3 -S atlas/samples/braess/verify.py assets/braess/open.json
# Отрисовка и тесты:
python3 -m venv .venv
.venv/bin/pip install -r atlas/samples/braess/requirements.txt
.venv/bin/python atlas/samples/braess/generate.py
.venv/bin/python -m unittest discover -s tests -p test_braess.py -v
```

Pillow 13.0.0 нужен только для GIF/PNG. Рисунки и код собственные, датасеты реальных дорог не используются. ZIP имеет фиксированные даты, все артефакты сравниваются при повторной генерации побайтно в одном окружении.

Восемь тестов: независимая проверка обоих равновесий для **каждого целого Q от 1 до 10000** и интервала вреда, точные граничные случаи, независимая проверка потенциала Бекмана на конечной грубой сетке (дополнительная проверка, не доказательство для всех потоков и не минимум общего времени), порча, строгие входы, опубликованные таблицы/контейнеры, автономный ZIP без site-packages и повторная генерация. Опциональный `check-browser.cjs` проверяет распакованный ZIP: все 182 сертификата, семь положений ползунка на разных режимах и границах, отказ после порчи, canvas, клавиатуру, сброс, мобильную ширину, отсутствие HTTP и JS-ошибок. npm-зависимости указаны в начале; минимальному Linux нужны библиотеки Chromium.
