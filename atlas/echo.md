# Волна задом наперёд

18 ноября 2026. Томография восстанавливала предмет из измерений. Здесь другая возможность вычислительной физики: **вернуть разошедшуюся волну, изменив состояние, а не развернув список картинок**.

Импульс расходится по двумерной решётке, отражается от закреплённых краёв и трёх препятствий. На шаге 240 сохраняем поле смещения `u`, меняем знак всех скоростей `v` и тем же интегратором считаем ещё 240 шагов вперёд. В идеальной бездиссипативной модели он возвращается к исходной форме.

Это **full-state reversal**, не эксперимент с реальной мембраной, не запись звука и не акустическое time-reversal mirror, управляемое только с границы. Последнее требует отдельной модели датчиков, источников, апертуры и сигналов. Здесь нам доступен каждый динамический узел — очень сильное идеализированное условие.

## Полное состояние — не один кадр

Модель постоянной скорости:

```text
u_tt = c² Δu
u_t = v
v_t = c² Δu
```

`u` — скалярное знаковое смещение, `v` — его производная по времени. Здесь `c = 1` клетка / условную единицу времени, расстояние между узлами равно 1. Края и препятствия закреплены: `u = v = 0`. Это Dirichlet, аналог закреплённого края идеальной мембраны. **Не** Neumann-условие акустической жёсткой стенки; цвета не показывают звуковое давление или интенсивность.

Два состояния с одинаковым `u` и разным `v` выглядят на картинке одинаково, но дальше развиваются по-разному. Поэтому кнопка «обратить» не может честно работать с одним PNG. Мы публикуем [checkpoint.npz](../assets/echo/checkpoint.npz) с `u`, `v` и `fixed`: NumPy-массивы float64, float64 и bool, без pickle. В нём нет исходного импульса и истории.

Начало: гауссово смещение с центром `(0,24;0,34)` в нормированных координатах, ширина `σ = 0,033`, нулевая скорость, обнуление закреплённых узлов. Отдельные препятствия — два диска и короткая вертикальная планка. Это оригинальная простая геометрия, не оцифрованная реальная сцена.

## Как считается шаг

Сетка 112 × 112, пятиузловой Laplacian по незакреплённым узлам:

```text
L(u)[i,j] = u[i−1,j] + u[i+1,j] + u[i,j−1] + u[i,j+1] − 4u[i,j]
```

Фиксированные узлы не являются степенями свободы и всегда равны нулю. Полученный на свободных узлах оператор симметричный, неположительный. Это проверяется тестом.

Интегратор velocity Verlet, `h = 0,45`:

```text
v_half = v + (h/2) L(u)
u_next = u + h v_half
v_next = v_half + (h/2) L(u_next)
```

Для квадратной сетки с `c = Δx = 1` безопасный предел `h ≤ 1/√2 ≈ 0,7071`; выбранный шаг ниже него. Вырезанные фиксированные узлы не увеличивают верхнюю оценку максимальной частоты полного stencil. Наличие обратимости **не доказывает** точность аппроксимации непрерывной PDE: численная дисперсия всё ещё есть.

Если `R(u,v) = (u,−v)`, симметричный шаг удовлетворяет `R S_h R = S_h⁻¹`. Поэтому:

```text
S_h^240 R S_h^240 (u0, 0) ≈ (u0, 0)
```

Остаток — floating-point roundoff. При ненулевой исходной скорости конец был бы `(u0,−v0)`, а не `(u0,v0)`.

[wave_local.py](samples/echo/wave_local.py) не знает начального импульса, изображения, списка кадров и цели. Он содержит только динамику и энергию. [resume.py](samples/echo/resume.py) читает полный checkpoint, применяет выбранную операцию и запускает шаги — его можно использовать **без генератора, PNG и исходного состояния**.

## Три контрольных опыта

На шаге 240 состояние одинаково для всех веток. После операции считаются ещё 240 положительных временных шагов, а не отрицательное время:

| Операция на скоростях | Относительная ошибка смещения после возврата |
| --- | ---: |
| `v → −v` | 1,3573 × 10⁻¹⁵ |
| `v → 0` | 0,67094290 |
| Оставить `v` | 1,34188580 |

Метрика — `||u_final − u_initial||₂ / ||u_initial||₂` по всем 112 × 112 узлам, **до** цветового отображения. Это не процент физической точности. Для полного разворота также измерен `||v_final||₂/||u_initial||₂ ≈ 1,7151 × 10⁻¹⁵`; это нормированный численный остаток в выбранных условных единицах, не безразмерная универсальная мера скорости.

### Почему обнуление скоростей оставляет половину эха

В линейной системе:

```text
(u, 0) = ½ (u, v) + ½ (u, −v)
```

Поэтому после одинакового числа шагов ветка «обнулить» равна полусумме веток «оставить» и «обратить» **по полю**, не по цветам и не по интенсивности. Она частично собирается, но поверх фокуса остаётся рассеянный вклад. Ошибка вдвое меньше, чем у «оставить», именно по этой причине, а не из-за красивого совпадения. Это отдельно проверяется численно.

В GIF первая фаза показывает распространение. Во второй слева обращены скорости, справа их оставили неизменными. Все 61 отображаемый кадр получены вычислением; возвращающиеся поля не взяты из первого участка в обратном порядке. Пауза/скачок при повторе GIF — контейнерная петля, не дополнительная физическая стадия.

## Энергия: что сохраняется на самом деле

Обычная дискретная энергия:

```text
E = ½ vᵀv − ½ uᵀLu
```

Verlet не сохраняет её идеально в каждом шаге. На опубликованной траектории максимальное относительное отклонение — **0,00619094**, около 0,619 %. Не следует выдавать её за «строго постоянную».

Для именно этого линейного оператора и шага точным квадратичным инвариантом схемы служит модифицированная энергия:

```text
E_h = E − (h²/8) ||Lu||²
```

На траектории её относительный дрейф не больше **5,75 × 10⁻¹⁶**. Симметричность временного шага и почти постоянный инвариант — численные проверки реализации, не независимая экспериментальная валидация реальной среды.

[trace.csv](../assets/echo/trace.csv) публикует энергию, модифицированную энергию и ошибку смещения на каждом шаге прямой и обращённой веток. Энергия контрольной ветки с обнулением скоростей закономерно меняется в момент вмешательства; она не включена в утверждение о сохранении инварианта основной траектории.

## Цвет не подменяет расчёт

Для всех полей **одна** знаковая шкала `tanh(5u)`: тёмный ноль, янтарные положительные значения, бирюзовые отрицательные. Нет отдельной нормировки каждого кадра, иначе слабая рассеянная волна могла бы выглядеть столь же сильной, как исходный фокус. Это нелинейное отображение для видимости, не карта энергии. Закреплённые узлы серые.

## Живой опыт без сети

[bench.zip](../assets/echo/bench.zip) содержит единственный HTML, без зависимостей, PNG, checkpoint, видео и внешних запросов. После распаковки открой `bench.html`:

1. «До конца фазы» — рассчитать 240 шагов рассеяния.
2. Выбрать, что сделать со скоростями.
3. Ещё раз «До конца фазы» — рассчитать возврат/контроль.
4. «Сначала» — повторить с другой операцией; `+12 шагов` позволяет наблюдать постепенно.

Выбор блокируется только после первого шага второй фазы, чтобы режим не менялся посреди опыта. Никакого autoplay, `setInterval` и `requestAnimationFrame`: приложение считает по нажатию. На конце кнопки шагов заблокированы; reset остаётся доступен. Есть клавиатурное управление, подписи полей и текстовая L2-метрика.

В HTML хранится начальная форма для создания опыта и подсчёта ошибки; **шаг интегратора и возврат её не используют**. История кадров не сохраняется. Память состояния — текущее `u,v` плюс рабочие массивы и target для метрики. Это принципиально отличается от загрузки уже посчитанного GIF.

В самом README JS не выполняется: там GIF, reduced-motion PNG, alt и ссылки. Локальный файл — отдельный опыт, не скрытая возможность GitHub Markdown.

## Честные границы

- Это идеальное управление скоростями **во всех узлах** без ошибки и с известной неизменной средой. Не реалистичная технология обращения времени.
- Нет damping, absorption, PML, шума, ограниченной апертуры датчиков и неизвестной геометрии.
- Восстанавливается дискретное состояние той же схемы: очень малая ошибка возврата не устраняет spatial/temporal discretization error.
- Не shallow-water solver, не моделирование настоящей воды, не акустический расчёт жёстких стен, не waveform inversion и не медицинское/сейсмическое исследование.
- Изображение показывает скалярное смещение, не вещественную траекторию движения среды и не звук. Аудиофайл намеренно не генерируется.

## Повторить

```sh
python3 -m venv .venv
.venv/bin/pip install -r atlas/samples/echo/requirements.txt
.venv/bin/python atlas/samples/echo/generate.py

# Только checkpoint и шаговый интегратор; исходный импульс не нужен:
.venv/bin/python atlas/samples/echo/resume.py \
  assets/echo/checkpoint.npz --mode reverse --output /tmp/returned.npz
.venv/bin/python atlas/samples/echo/resume.py \
  assets/echo/checkpoint.npz --mode zero --output /tmp/zero.npz
.venv/bin/python atlas/samples/echo/resume.py \
  assets/echo/checkpoint.npz --mode keep --output /tmp/continued.npz
```

`generate.py --output /tmp/echo` делает отдельный комплект, не меняя README. NumPy/Pillow закреплены в requirements; ZIP/NPZ имеют фиксированную дату. CLI принимает только собственный формат полного checkpoint, а не произвольные записи чужих симуляторов.
