# Afterlight: что ещё можно выжать из README

Исследовательская заметка, 18 ноября 2026. Старые экспонаты сохранены; новый зал добавляет 12 самостоятельных изображений и настоящие файлы для нативных просмотрщиков. Это не список обещаний: рядом с каждым приёмом есть ограничения. Документация описывает возможности платформы, но не заменяет проверку в целевых браузерах.

## Три разные поверхности

| Поверхность | Что туда подходит | Чего не ждать |
| --- | --- | --- |
| Сам README | GFM, таблицы, формулы, alerts, картинки, `picture`, `details`, разрешённый HTML | Произвольных CSS, JS, iframe, WebGL и рабочего приложения |
| SVG как изображение | Геометрия, градиенты, маски, обтравки, фильтры, CSS-анимация, текст по кривой | Кликабельных внутренних кнопок, доступа к DOM README, сетевых веб-шрифтов |
| Отдельная страница файла | Нативные таблицы CSV/TSV, PDF, notebook, карты, STL, Mermaid | Что весь этот интерфейс автоматически встроится в `<img>` |

GitHub перечисляет CSV/TSV, PDF, GeoJSON/TopoJSON, STL, notebooks и `.mmd`/`.mermaid` среди поддерживаемых форматов. CSV/TSV имеют поиск; для таблиц документирован предел 512 KB. Notebook показывается как статический HTML: Python и интерактивный JavaScript на странице файла не исполняются. Ссылки внутри PDF в просмотрщике GitHub игнорируются. [1](https://docs.github.com/en/repositories/working-with-files/using-files/working-with-non-code-files)

Встраивание схем через ограждения `mermaid`, `geojson`, `topojson` и `stl` тоже поддерживается. В этой галерее намеренно остаются лёгкие иллюстрации и ссылки на файлы, чтобы не множить тяжёлые просмотрщики на длинной странице. [2](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/creating-diagrams)

## Новые рабочие материалы

- [CSV](../assets/afterlight/catalog.csv) и [TSV](../assets/afterlight/catalog.tsv) — один и тот же каталог; размер SVG посчитан генератором, не взят с потолка.
- [Notebook](../assets/afterlight/phyllotaxis.ipynb) — код построения подсолнуха и уже сохранённый SVG-вывод. Для повторного исполнения локально нужны Python, Jupyter и IPython; для генерации всех файлов — только стандартная библиотека Python.
- [Отдельный Mermaid-файл](samples/afterlight/surfaces.mmd) — схема выбора поверхности. В README он не подключает ещё один JS-рендерер.
- [SVG-филлотаксис](../assets/afterlight/phyllotaxis.svg) — тот же алгоритм в самостоятельной карточке.

## Почему именно эти 12 приёмов

| Приём | Механизм | Куда поставить |
| --- | --- | --- |
| Муар | Две повёрнутые частые решётки и `clipPath` | Оптическая заставка, разделитель |
| Маятниковая волна | Разные целочисленные частоты, CSS `transform-origin` | Демонстрация алгоритма, научный профиль |
| Гармонограф | Параметрическая кривая + однократное рисование штриха | Подпись или заставка без вечного мигания |
| Филлотаксис | Золотой угол, радиус пропорционален √n | Генеративный аватар или знак |
| Топографический шёлк | Семейство аналитических кривых | Спокойная статичная обложка |
| Метасферы | `feGaussianBlur` → порог альфа через `feColorMatrix` | Жидкий логотип, интро |
| Гильош | Высокочастотная радиальная модуляция | Рамка, сертификат, печатная графика |
| Поворот плитки | Одна дуга, повторение, CSS-повороты | Бесшовный визуальный мотив |
| Текст по кривой | `textPath` + локальный `href` | Нестандартный заголовок |
| Проволочный объём | Проекции эллипсов | Иллюзия 3D без модели |
| Фазовые дорожки | `stroke-dashoffset` | Разделитель с направлением потока |
| Цифровая бумага | `feTurbulence`, фиксированный seed | Зерно без растровой текстуры |

Все рисунки свои, генерируются без внешней графики и веб-шрифтов. У карточек есть `title`, `desc`, контрастная собственная подложка; смысл повторяется в подписи README. Они не изображают реальную статистику аккаунта. CSS-анимации выключаются через `prefers-reduced-motion: reduce`; исходное состояние остаётся полноценным рисунком. У гармонографа финальный рисунок — базовое состояние, а не пустой лист. Маятники — наглядная стилизация частот, не модель силы тяжести.

## Ещё приёмы, которые стоит знать

### Тема, ширина экрана и движение — три независимых условия

GitHub официально показывает смену изображения через `<picture>` и `prefers-color-scheme`. Не пытайся определить тему страницы из CSS внутри внешнего SVG: выбирай варианты в README через `source media`. [3](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/quickstart-for-writing-on-github)

```html
<picture>
  <source media="(prefers-reduced-motion: reduce)" srcset="assets/static.svg">
  <source media="(max-width: 600px)" srcset="assets/compact.svg">
  <source media="(prefers-color-scheme: dark)" srcset="assets/dark.svg">
  <img src="assets/default.svg" alt="Краткое описание содержимого">
</picture>
```

Это рецепт с условными именами, не ссылки на существующие файлы. Порядок важен: выбирается первый подходящий `source`. Для комбинирования темы и ширины нужны объединённые media-условия. Если у картинки есть SMIL (`animate`, `animateMotion`), простое отключение CSS-анимации её не остановит: надёжнее отдельный статичный файл через `picture`. Наш прежний «Север» уже демонстрирует такую развилку; новые карточки вообще не используют SMIL.

### HTML/CSS внутри SVG: интересно, но не основа галереи

Техника `foreignObject` позволяет разместить XHTML и стили внутри SVG; есть публичный разбор с CSS-анимацией и `prefers-reduced-motion`. Это **изображение с изолированным содержимым**, не способ изменить стили остального README. Поддержка экспорта и некоторых браузеров отличается: для основных экспонатов здесь выбран обычный SVG без `foreignObject`. [4](https://pragmaticpineapple.com/adding-custom-html-and-css-to-github-readme/)

Список HTML-тегов в HTML Pipeline полезен для изучения санитаризации: фильтр удаляет `style`, обработчики событий и скрипты. Но текущий код библиотеки — не контракт точной конфигурации github.com. Не строй оформление на предположении, что `style="..."`, `<iframe>` или инлайн-`<svg>` пройдут в README. [5](https://github.com/gjtorikian/html-pipeline)

### Форматирование без единой картинки

Таблица с короткими колонками, настоящая сноска, `<dl>` для словаря, `<kbd>` для клавиш, `<sub>`/`<sup>`, ruby-подписи, `<ins>`/`<del>`, выравнивание ячеек GFM, раскрывающийся исходник и математическая формула часто полезнее очередного бейджа. Основные конструкции и сноски описаны в документации GFM GitHub. [6](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax)

Важно различать контексты: автопревью цветовых значений в Issues/PR — не универсальный виджет README; загрузка видео-вложения — не разрешение вставлять произвольный YouTube iframe. Не выдавай SVG-прогресс за живой индикатор, если за ним нет обновляющего workflow.

## Что сознательно не добавлено

Счётчики слежения за посетителями, Spotify с OAuth, десятки внешних виджетов и workflow с широкими правами. Для декоративной галереи это лишние зависимости и секреты. Не меняем чужую анимацию и не приписываем ей своё авторство. Новые экспонаты локальные; никакие реальные метрики не подменены учебными.

## Повторить

Из корня репозитория:

```sh
python3 atlas/samples/afterlight/generate.py
python3 -m unittest discover -s tests -v
```

Или независимая печать без изменения репозитория:

```sh
python3 atlas/samples/afterlight/generate.py --output /tmp/afterlight
```

Генератор намеренно не редактирует README. Проверки сравнивают чистую перепечатку побайтно, проверяют каталог, ссылки, структуру SVG и сохранённый notebook. Это не автоматическое доказательство одинакового рендера всех браузеров: особенно фильтры и системные шрифты могут отличаться.
