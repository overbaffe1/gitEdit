# 32 лампочки хранят все 32 слова

Циклическая двоичная последовательность де Брёйна **B(2,5)**: 32 бита, в которых каждое из 32 слов длины пять встречается ровно один раз. Направление чтения — **по часовой стрелке**, начало окна — любая из 32 клеток. После клетки 31 идёт клетка 0. В неподвижном примере начало окна 29: оно читает клетки **29, 30, 31, 0, 1** и даёт `00001`.

## Почему это минимум, но не сжатие

У кольца длины L ровно L возможных начал окна фиксированной длины. Для 32 различных слов требуется **L ≥ 32**. Предъявленная лента достигает этого предела: это оптимальная длина **цикла**, содержащего все двоичные пятибитные слова.

У линейной строки длины L только **L−4** окон длины пять. Значит, для неё требуется **L ≥ 36**. Достаточно разрезать наше кольцо и приписать в конце первые четыре бита: получится ровно 36 символов и все 32 окна. Без повторённого хвоста прямая запись 32 бит даёт лишь **28** окон; четыре окна пересекают шов кольца.

Никакие произвольные 32 независимых пятибитных сообщения тут не сжимаются. Это одна специальная последовательность, соседние слова в которой разделяют четыре общих бита. Таблица позиций просто задаёт перестановку слов и позволяет выбрать положение окна. Кольцо не хранит 160 произвольных бит полезной нагрузки.

Также не заявляются случайность, криптографическая стойкость, коррекция ошибок или уникальное декодирование при неизвестном направлении/сдвинутых физических границах клеток. Любое пятибитное слово уже допустимо: по одному окну нельзя обнаружить ошибку чтения. Стенд обнаруживает порчу потому, что проверяет **всю ленту**.

## Построение: все рёбра, а не все вершины

Вершины графа — 16 четырёхбитных слов. Из каждой выходят два ориентированных ребра: дописать 0 или 1 и забыть самый старый бит. Например, `0101 → 1010` и `0101 → 1011`. Каждое ребро соответствует пятибитному слову: исходные четыре бита плюс дописанный бит. Всего 32 ребра.

У каждой вершины два входа и два выхода. Из любой вершины можно попасть в любую другую, последовательно дописав четыре бита целевой вершины, поэтому граф сильно связен. Следовательно, есть замкнутый эйлеров обход: пройти **каждое ребро ровно один раз**. Это не гамильтонов обход из предыдущего экспоната: повторять вершины разрешается и требуется.

`construct.py` реализует детерминированный обход Хиерхольцера стеком: сначала пробует ребро 0, потом 1, а метки закрываемых рёбер разворачивает в конце. Записанные метки дают цикл. Пять последовательных меток — ровно слово соответствующего ребра, поскольку любые предыдущие четыре перехода определяют текущую вершину. Поэтому все 32 слова встретятся один раз.

Для фиксированного порядка n обход имеет 2^n рёбер, а не перебирает все возможные двоичные строки длины 2^n. Реализация ограничена **целыми n от 1 до 10**: это сознательный предел интерфейса/памяти. Публичный HTML и рисунки фиксированы на n=5; параметрические построение и независимая проверка тестируются на всех n=1…10. Программа строит **один** цикл, не считает и не перечисляет все циклы. Сдвиг, отражение или замена 0↔1 также сохраняют свойство, но могут менять позиции слов.

## Проверка без доверия к обходу

`verify.py` не импортирует конструктор и не ищет эйлеров обход. Он требует правильный формат, целое n в допустимых границах, строку только из 0/1 длины ровно 2^n. Затем заново считывает все циклические окна и сравнивает их с полным декартовым произведением алфавита. Каждое слово должно иметь кратность **ровно один**. При успехе печатает таблицу `слово → индекс начала`.

В сертификате нет заранее доверенной таблицы: `bits` и `order` — единственные математические входные данные. Проверяющий отвергает пропуски, повторы, неверную длину, чужой алфавит, дробный/булев порядок и порядок вне диапазона. Это конечная математическая проверка, не криптографическая подпись и не защищённый парсер неограниченных недоверенных файлов.

Для основной ленты проверены все **32 одиночные инверсии бита**: каждая портит свойство полного цикла и отвергается. Это проверка конкретного семейства повреждений, а не обещание исправления/обнаружения всех возможных ошибок. Например, другая правильная последовательность будет принята, и это правильно.

Независимый дополнительный тест не использует модульное считывание проверяющего: строит линейную строку `bits + bits[:4]`, берёт 32 обычных среза и сравнивает мультимножество с `product('01', repeat=5)`.

## Стенд и бумажная версия

Распаковать ZIP, открыть `necklace.html` напрямую через `file://`. Сети, сервера, CDN, fetch соседних JSON, веб-шрифтов и установки зависимостей не требуется. Ползунок/стрелки выбирают начало; 32 кнопки находят заданное слово. Можно проверить все окна, испортить **отдельную копию** первого бита и вернуть исходную ленту. Исходная строка не меняется; при порче пропавшие слова отключаются в списке, а полная проверка показывает пропуски/повторы. Автопроигрывания в HTML нет.

Canvas дублируется текстом выбранного слова, позиции, всей ленты и линейной версии; ползунок имеет подпись, кнопки доступны с клавиатуры. Анимация README — просто последовательные положения окна, не процесс поиска цикла. Для reduced-motion предусмотрен PNG. GitHub не исполняет наш JavaScript внутри README: интерактивность находится в скачиваемом пакете.

Печатать SVG на A4 в **100 %**, без подгонки. Четыре полоски по восемь клеток шириной 10 мм собираются в порядке **1 → 2 → 3 → 4 → 1**. Клапаны TAPE уходят **под следующую полоску**, не являются дополнительными битами и не должны закрывать напечатанные клетки. Итоговое кольцо содержит 32 клетки; окно 50 мм захватывает пять. Схема окна на том же листе задаёт размер; вырезать окно удобнее в отдельном обрезке бумаги. Физическая точность печати/склейки не является частью математического свидетельства.

## Воспроизведение

```sh
# Стандартная библиотека; также работает из распакованного ZIP:
python3 -S atlas/samples/necklace/verify.py assets/necklace/certificate.json
# Рисунки/анимация и тесты:
python3 -m venv .venv
.venv/bin/pip install -r atlas/samples/necklace/requirements.txt
.venv/bin/python atlas/samples/necklace/generate.py
.venv/bin/python -m unittest discover -s tests -p test_necklace.py -v
```

Pillow **13.0.0** нужен для GIF/PNG; алгоритмы/проверка — stdlib. Рисунки, UI, печатная схема и генератор собственные. Даты ZIP фиксированы; тест повторной генерации сравнивает все артефакты побайтно в одном окружении.

Восемь тестов проверяют n=1…10; все линейные окна отдельным оракулом; 96 вариантов поворотов/отражения/комплемента; все 32 одиночные порчи; строгие входы; JSON/CSV/GIF/ZIP и запуск `verify.py` с `-S`; перекрытие слов/биекцию позиций; повторную генерацию.

`atlas/samples/necklace/check-browser.cjs` проверяет распакованный ZIP через Chromium/file://: все 32 позиции совпадают с независимым Python-аудитом, все кнопки слов, шов и оба направления перехода через 0, порчу/восстановление, клавиатуру, canvas, мобильную ширину, отсутствие HTTP и JS-ошибок. npm-зависимости указаны в начале скрипта. В минимальном Linux нужны системные библиотеки Chromium.

## Что изучено на GitHub

[sources.json](samples/necklace/sources.json) фиксирует **семь успешных README-просмотров** и один неуспешный запрос README с SHA. Это просмотр описаний, не аудит семи реализаций: сторонние исходники/статьи/диссертации не анализировались, программы не запускались, чужие код, GIF и последовательности не копировались. Полные README были получены; для длинных описаний в выводе исследовались показанные части и отдельно выбранные фрагменты. Математическое доказательство выше самостоятельное и не выдаётся за новое открытие.
