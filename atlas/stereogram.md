# Скрытый рельеф: не анимация, а бинокулярное соответствие

18 ноября 2026. Ещё одна поверхность для README — **статичная случайно-точечная автостереограмма**. Рельеф задаётся горизонтальным расстоянием между одинаковыми фрагментами узора. Никакого исполнения кода при просмотре изображения не происходит.

Своя сцена — округлое выпуклое кольцо и маленький спутник справа сверху. Карта задана аналитически, шум детерминирован; чужих моделей, изображений, готовых карт глубины и кода в экспонате нет.

## Как смотреть — и когда не пытаться

Рассматривай [оригинал](../assets/stereogram/stereogram.png) на удобном расстоянии без растяжения по одной оси. Если знаком с автостереограммами, попробуй параллельное сведение: смотреть словно немного за поверхность экрана. Не нужно скрещивать глаза, подносить лицо вплотную, долго удерживать напряжение или добиваться результата любой ценой. Масштаб браузера, экран, интерполяция и индивидуальное зрение влияют на эффект.

**При дискомфорте прекрати просмотр. Если объёма нет — просто открой [раскрытие формы](../assets/stereogram/proof.png).** Это не медицинский тест, не диагностика и не оценка твоего зрения. Даже доказанные пиксельные соответствия не гарантируют одинакового восприятия у людей.

Карта глубины и описание доступны без стереозрения. Никакой важный текст, навигация или смысл проекта не спрятаны исключительно в эффекте.

## Устройство своего генератора

[generate.py](samples/stereogram/generate.py) использует Python, NumPy и Pillow. Входных файлов нет: сцена из двух собственных аналитических функций.

### 1. Высота, а не текстура

Карта `z` лежит в диапазоне 0…1: фон — 0, светлые участки ближе. Радиус кольца 124 пикселя, полуширина сечения 34; его округлое сечение достигает 0,9. Отдельный круглый купол достигает 0,75. Это карта относительной высоты, не измерения в миллиметрах.

### 2. Разделение пар

Для параметров `E = 160` пикселей и `μ = 0.4`:

```text
s(z) = round(E × (1 − μz) / (2 − μz))
left  = x − floor(s / 2)
right = left + s
```

На фоне расстояние **80 px**, на ближайшей части кольца — **62 px**. Меньшее расстояние кодирует более близкий рельеф для параллельного сведения. `E` — параметр растрового построения, не измеренная межзрачковая дистанция пользователя. При масштабировании картинки все расстояния на экране меняются.

### 3. Не склеить всё со всем

Кандидаты обрабатываются по возрастанию разделения — более близкий слой первым. На каждой строке сохраняется однозначное упорядоченное соответствие: уникальные левые/правые проекции, без инверсии порядка. Конфликтующие дальние пары не навязываются поверх ближних. Связи всегда идут вправо, поэтому образуют цепочки без циклов.

Каждая цепочка получает один псевдослучайный цвет из фиксированной палитры. Поэтому все принятые пары имеют **в точности одинаковые RGB**, но исходный силуэт не добавляется поверх шума. При смене текстурного seed геометрия пар остаётся прежней.

Это **дискретное приближение через упорядоченное сопоставление**, а не полноценный непрерывный трассировщик лучей с точным учётом всех окклюзий. На краях формы возможны ложные/неоднозначные соответствия. Ни отдельная красивая картинка, ни отсутствие исключений генератора не считаются достаточной проверкой.

## Проверка, которая не подглядывает в карту

Генератор сначала записывает PNG, затем декодер открывает именно этот файл. В функцию `decode` передаются только RGB-пиксели — **не карта, не seed, не цепочки и не таблица связей**. Диапазон поиска 60…80 px задан как общий параметр формата этого экспоната, поэтому это не универсальный solver для любой неизвестной стереограммы.

Для каждого разделения:

1. Сравниваются RGB пар в строке; несовпадение — 1, совпадение — 0.
2. Стоимость усредняется в окне **11 × 5**.
3. Выбирается разделение с минимальной стоимостью; при точном равенстве — более дальний фон.
4. По обратной формуле проекции восстанавливается относительная высота. Она квантована до целочисленных разделений, поэтому не обязана повторять плавный оригинал.

В [proof.png](../assets/stereogram/proof.png) сверху **исходная карта**, снизу **реально восстановленная из PNG**. Это разные данные, подписанные явно. [recovered.png](../assets/stereogram/recovered.png) — самостоятельный результат декодера, не копия `depth.png`.

### Измеренные результаты этого файла

Проверяемая область: `100 ≤ x < 860`, `10 ≤ y < 470`. Край изображения исключён явно, поскольку для него не всегда существует полная пара. Маска «переднего плана» в обоих случаях определена как разделение `< 77 px`.

- Средняя абсолютная ошибка разделения: **0,10647 px**.
- IoU масок переднего плана: **0,961876**.
- Размер PNG: 960 × 480. SHA256 и подробные параметры — в [facts.json](../assets/stereogram/facts.json).

Метрики относятся только к этому синтетическому изображению и выбранной области. Они не означают «96 % людей увидят объём», не измеряют эстетическое качество и не доказывают идеальную окклюзию. Для плоского контрольного изображения тест отдельно проверяет отсутствие придуманного рельефа в центральной области.

## Стол соответствий: локально и без сети

Скачай [bench.zip](../assets/stereogram/bench.zip), распакуй все три файла рядом и открой `bench.html` в обычном браузере. Доступны:

- ползунок по принятым соответствиям строки 240;
- выделение левого/правого пикселя и числовое разделение;
- раскрытие **исходной** карты глубины;
- сброс к узору и первому соответствию.

Это инспектор заранее рассчитанного изображения, не живой генератор и не нейросетевой декодер. Он не модифицирует PNG, не выполняет сетевых запросов, не сохраняет состояние и ничего не проигрывает. Карта — доступная альтернатива эффекту; ползунок не требуется для прохождения какого-либо задания.

Внутри `<img>` GitHub не запускает JS. В README раскрытие — **обычная ссылка на другой PNG**. На странице `bench.html` GitHub показывает код; для рабочего интерфейса нужен скачанный комплект. Готовый PNG можно использовать без Python, HTML, токенов, workflow и внешнего хостинга.

## Повторение

```sh
python3 -m venv .venv
.venv/bin/pip install -r atlas/samples/stereogram/requirements.txt
.venv/bin/python atlas/samples/stereogram/generate.py
# Декодировать только пиксели PNG, не генерируя сцену заново:
.venv/bin/python atlas/samples/stereogram/generate.py \
  --decode assets/stereogram/stereogram.png --output /tmp/recovered.png
.venv/bin/python -m unittest discover -s tests -v
```

Без аргументов генератор пишет только в `assets/stereogram/`. Для отдельной перепечатки есть `--output /tmp/stereogram`. В режиме `--decode` выход — **файл PNG**, а не каталог. Сеть и входные фотографии не нужны, корневой README генератор не редактирует. ZIP имеет фиксированные даты для воспроизводимости. Зависимости старых экспонатов для полного набора тестов устанавливаются отдельно.

**Где это уместно:** один запоминающийся экспонат для проекта о компьютерном зрении, сопоставлении изображений или скрытых данных. Не используй стереограмму вместо обязательной схемы, инструкции или доступного текста.
