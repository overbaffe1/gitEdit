# Большая экспедиция по GitHub: 102 репозитория и одна настоящая находка

18 ноября 2026. В этот раз задача была не добавить похожие орнаменты, а найти другой тип взаимодействия с README. Результат — **«Станция Палимпсест»**, собственный иллюстрированный квест из обычных Markdown-страниц. Дверь — ссылка, инвентарь — часть имени файла. Никакого сервера, JavaScript, Issues или записи в репозиторий при игре.

## Масштаб и честные границы исследования

- 106 запросов README по кандидатам из четырёх поисковых направлений и профильных подборок.
- 103 успешных ответа; после объединения алиасов по каноническому URL — **102 уникальных репозитория**.
- Первичный обзор: структура README, выбранные содержательные фрагменты, ссылки на изображения, упоминания workflow, терминала и внешних сервисов. **Это не полное чтение всего исходного кода 102 проектов и не аудит безопасности.**
- Для **8 репозиториев** дополнительно просмотрены **9 конкретных файлов**: workflow, Python, JavaScript, SVG и notebook-генератор.
- Список всех 102 — в [CSV](samples/expedition/survey.csv). Там есть путь README, его Git blob SHA, размер, уровень просмотра и синтаксические маркеры. Для глубоких выборок сохранены ссылки на конкретные коммиты в [JSON](samples/expedition/sources.json).
- README-файлы скачивались только для анализа. Чужие исходники, длинные цитаты и коллекции картинок в репозиторий не перенесены. Неудачные запросы перечислены отдельно и в число 102 не входят. Два разных адреса одного проекта не засчитаны дважды.

Маркеры в CSV — только наблюдения: наличие `.svg` не доказывает автономность картинки, `workflow` не означает, что workflow сейчас успешно запускается, ссылка `issues/new` не означает, что игра ещё обслуживается. Внешние игры не запускались, ходы не отправлялись, Issues не создавались. Профили и README могут измениться после даты обзора.

## Девять исходных файлов: что именно посмотрено

Закреплённые ссылки и SHA — в JSON; здесь выводы, а не скопированные реализации.

1. **JonathanGin52 / `.github/workflows/connect4.yml`**: событие `issues: opened`, фильтр по префиксу `connect4|`, запуск Ruby с токеном и данными Issue.
2. **marcizhu / `.github/workflows/Chess.yml`**: событие Issue, Python, коммит/push, отдельный webhook. Значит, общий игровой мир живёт за пределами Markdown-рендера.
3. **Readme-2048 / `main.py`**: разбор команд из заголовка Issue, JSON текущей игры, блокировка двух последовательных ходов автора и переписывание выделенного блока README.
4. **kylepls / `generate.ipynb`**: дерево состояний, поиск ходов, ID узлов и компиляция игрового дерева в один README с якорями. Это главный технический ориентир нового экспоната — **вычислить конечные состояния заранее**.
5. **nagare / `flow.py`**: недельные вклады превращаются в течения через сглаживание и нелинейную шкалу. Искусство может быть объяснимой визуализацией, а не просто декорацией.
6. **nagare / `render.py`**: темы, CSS-поток и SMIL-рябь. Нельзя обещать, что одно отключение CSS остановит любой SVG.
7. **vaaski / `space-logo.svg`**: самостоятельные SVG-градиенты, обтравка и SMIL-перемещение звёзд. JS README для такого эффекта не нужен.
8. **ascii-magic-art / `lib/scene.js`**: RGB-canvas, маски объектов, палитра, разделение фона и движения. Библиотечный runtime — не сам формат Markdown.
9. **simonw / `.github/workflows/build.yml`**: расписание, сборка с токеном, коммит только при изменениях. Это долговременная автоматизация, не мгновенный рендер для посетителя.

Изучение этих файлов не является рекомендацией переносить старые версии action, разрешения или shell-команды. Существующие внешние workflow здесь не запускались. Код и графика нового квеста самостоятельные; общие идеи конечного автомата и гиперссылок не привязаны к чужой реализации.

## Что добавлено: станция «Палимпсест»

[Войти через док](wayfinder/r00-i0.md). Найди **ключ** в мастерской и **линзу** в обсерватории, затем верни свет маяку.

- Девять комнат с собственными изометрическими иллюстрациями.
- **32 достижимых состояния**, а не 32 случайных страницы. Состояние — пара `(комната, инвентарь)`; два бита кодируют два предмета.
- Предмет подбирается автоматически при входе в его комнату. Биты не исчезают, пока ты идёшь вперёд по игровым ссылкам.
- Соседние комнаты связаны направлениями в Markdown-таблице. Стены — просто текст, не ссылки на недоступный ход.
- Выход до сбора двух предметов не победный: страница пишет, чего не хватает, и позволяет вернуться.
- Никаких локальных якорей, query-параметров или обработчиков клика. Каждый ход — переход на существующий `.md`.
- Начальный README получил только вход, иллюстрацию и описание. Дерево состояний не раздувает главную страницу.

### Почему это действительно работает без движка

Генератор обходит граф из начального состояния, выпускает все достижимые страницы и подписывает каждую ссылку конкретным следующим состоянием. Браузер выполняет навигацию, GitHub — обычный Markdown-рендер. Ничего не нужно вычислять при клике. Игра не пишет файлы, не создаёт Issue, не расходует минуты Actions и не требует входа в аккаунт для чтения публичного репозитория.

Это отличается от большинства community-игр в обзоре: **здесь нет общего серверного состояния**, ход одного посетителя не двигает другого.

### Что хранится и чего нет

URL страницы содержит состояние. Закладка или скопированная ссылка сохраняет позицию и предметы. Кнопка Back откатывает ход вместе с инвентарём; «Начать заново» ведёт в док без предметов. Это не autosave, cookie, база данных или защищённый профиль игрока.

Все страницы открыты: при желании можно напрямую открыть финал, подменить состояние ссылкой или посмотреть весь граф. Это не соревнование и не система прав доступа. В рисунках показаны символы комнат, поэтому изображение ключа не обязано исчезать после подбора — актуальный инвентарь написан текстом.

### Ограничение метода

Число страниц растёт с числом состояний: при `n` независимых предметах возможны до `комнаты × 2ⁿ` комбинаций. Здесь два предмета и девять комнат, поэтому весь мир маленький и проверяемый. Не стоит компилировать в Markdown сложную RPG, генеративный бесконечный лабиринт или секреты, которые нельзя раскрывать.

### Доступность и управление

У каждого перехода есть текст «направление: комната». Картины не обязательны: названия, описание, инвентарь и недостающие предметы доступны текстом. Работают обычные Tab/Enter и история браузера. Кнопки со стрелками клавиатуры, 3D-поворот и кликабельные двери внутри SVG не реализованы и не обещаются.

## Воспроизведение и тесты

```sh
python3 atlas/samples/expedition/generate.py
python3 atlas/samples/expedition/generate.py --output /tmp/palimpsest
python3 -m unittest discover -s tests -v
```

Только стандартная библиотека Python. Альтернативный `--output` — корень нового дерева с `atlas/wayfinder/` и `assets/wayfinder/`, а не папка одной картинки. Генератор не меняет корневой README и не делает сетевых запросов. Реестр обзора — отдельный датированный результат исследования; генератор игры его не обновляет и не называет живым поиском.

Тесты проверяют достижимость всех выпущенных страниц, возможность победить из каждого состояния, подбор/сохранение предметов, отсутствие недопустимых ходов, корректность каждой ссылки и совпадение чистой перепечатки. Отдельно проверяется, что ни один игровой переход не ведёт к API, Issues, query-команде или локальному якорю.

**Идея для своего проекта:** так можно сделать не только квест, но и ветвящийся комикс, пошаговый туториал, экскурсию по архитектуре или интерактивный выбор примера. Важно честно называть это навигацией по заранее подготовленным состояниям, а не исполнением приложения внутри README.

### Результат проверки этого выпуска

- Полный набор: **108 тестов прошли**, без пропусков.
- Сравнение с README до вставки: все старые байты сохранены в прежнем порядке, добавлен только новый раздел.
- GitHub Markdown API отрендерил страницу резонатора с ключом: изображение комнаты и переходы к обсерватории с двумя предметами / к маяку только с ключом сохранены.
- Док визуально проверен после статического SVG-рендера. Это проверка иллюстрации и серверного Markdown, не заявление о полноценном кликовом E2E в браузере GitHub.
