# Поиск следующей настоящей возможности GitHub README

Дата исследования: 18 ноября 2026. [Назад в галерею](../README.md).

**Результат этого прохода — исследование, не новый работающий экспонат.** Корневой README, workflows и существующие демонстрации не менялись. Не добавляем ещё один плакат ради количества.

## Лучший кандидат: настоящий видеоплеер

В отличие от GIF/APNG это возможность остановить ролик и перейти к нужному моменту. Подходящий экспонат — короткий авторский разбор геометрии: цельная модель → разнесённые детали → каркас → сборка. Это заранее записанное видео, не управляемая пользователем 3D-модель.

Что подтверждено:

- В документации GitHub CLI появился `--attach` у команд создания/редактирования/комментариев Issues и PR. Документирован результат в виде загруженного URL и inline-плеера для видео.
- В исходниках **CLI v2.105.0** действительно есть этот механизм. `videoAsset.markdown` возвращает голый URL, а комментарий поясняет: он должен занимать отдельный абзац. Картинка `![](local.mp4)` — лишь вход для переписывания CLI, не способ проиграть локальный файл в README.
- Загрузчик обращается к `https://uploads.github.com/user-attachments/assets`, требует разрешение записи и может не принять некоторые типы токенов GitHub Apps. Наличие прав Git на push само по себе не доказывает, что загрузка пройдёт.
- Видео не имеет alt-атрибута в этом механизме; нужно сопровождающее описание и текстовый эквивалент содержания.
- Код допускает MP4/MOV/WebM; локальный верхний предел CLI 100 MiB не гарантирует такой же лимит плана аккаунта. Сам файл всё равно должен быть корректным и поддерживаться клиентом.

**Что не подтверждено в этой сессии:** собственное загруженное вложение, воспроизведение этого вложения в корневом README, браузерные controls на GitHub и мобильных устройствах. Документация `--attach` непосредственно описывает Issues/PR/comments; перенос URL в README требует отдельной проверки. Markdown API не заменит проверку конечного плеера.

### Почему сейчас нет готового плеера

В окружении установлен CLI **2.23.0**, у которого нет нужного флага. API Releases показал актуальный релиз **v2.105.0**. Одна попытка скачать официальный Linux amd64 архив завершилась ошибкой TLS при переходе на `release-assets.githubusercontent.com`: этот хост не разрешён исходящей сетью среды. Новый CLI не установлен.

Даже установка бинарника не решает вторую границу: `uploads.github.com` также отсутствует среди разрешённых хостов. Запрос загрузки не отправлялся, токены не извлекались, обход сетевых ограничений не предпринимался. Не создавались пробные Issues, комментарии, Releases и вложения.

Таким образом, прежнее ограничение «этот установленный CLI не умеет attachments» остаётся верным для версии 2.23.0, но **не должно обобщаться на современный GitHub CLI**.

### Корректный путь до демонстрации

1. Сделать собственный короткий MP4 с постером и текстовым описанием; без чужих материалов, музыки и зависимости от автозапуска.
2. В среде с разрешёнными загрузками прикрепить его к описанию рабочего PR через современный CLI или браузер. Не использовать Issue лишь как скрытую базу ходов.
3. Взять **фактически полученный**, а не выдуманный URL вложения и проверить отдельным абзацем в Markdown на GitHub.
4. Только после проверки плеера в README добавить блок в галерею, сохранив старый README. Если там работает лишь ссылка — так и назвать и не объявлять встроенным плеером.
5. Проверить паузу, перемотку, отсутствие принудительного autoplay и текстовую альтернативу. Не обещать одинаковый fullscreen/controls во всех браузерах.

Обычная ссылка на MP4 в Git или Release не считается доказательством нативного проигрывателя. Здесь не публикуется фиктивный URL и не подставляется чужой ролик, чтобы создать видимость успеха.

## Проверка громких «игр прямо в README»

| Репозиторий / изученный материал | Реальный механизм в просмотренных файлах | Вывод |
|---|---|---|
| `losehu/losehu`, README | 2048, направления ведут на `issues/new`; README просит отправлять Issue, ход занимает около 10 секунд | Общая игра через Issue, не локальная интерактивность внутри Markdown. Автоматика по одному README не аудирована. |
| `QwertyL0L/README-Games`, README | Требуется скачать репозиторий, поставить requirements, заполнить config и запустить игру; затем обновлять страницу | Нужен внешний по отношению к GitHub-рендеру процесс. Не обещаем JS-игру в README. |
| `Tech-Codes/readme-games`, README | Статистические картинки с внешних API, анимации snake/pacman/dino и ссылка Play Pixel Hunter на GitHub Pages | Движущаяся картинка — не управление игрой. Ссылка Play ведёт на отдельный сайт. |
| `robalb/readme-games`, `games/increment.md`, `action.php` | Markdown-шаблон со ссылкой `%action%increment`; PHP принимает действие, вызывает чтение/запись состояния и перенаправляет браузер | Внешний backend, не скрытая функция GitHub. Полного аудита безопасности сервера нет, код не запускался. |

Эти проекты не объявляются плохими: просто их устройство не соответствует цели «как вращаемый STL прямо в README, без подмены внешним приложением».

## Ещё один проверенный тупик: 3D diff

Поиск нашёл `beastlike/testSTL` с описанием «test of github STL diff», но README API вернул 404. По одному названию нельзя обещать работающий трёхмерный diff.

В прочитанном текущем документе GitHub `working-with-non-code-files` описаны вращение, перенос, масштабирование и режимы STL-viewer, а визуальный diff описан отдельно для изображений. Подтверждения отдельного современного **3D diff** в этом документе не найдено. Это не доказательство его невозможности во всех версиях UI, но недостаточная основа для нового обещания.

## Что уже есть и потому не выдаётся за новинку

- STL/WebGL, карты GeoJSON/TopoJSON, Mermaid.
- Картинный Swipe/Onion Skin и rich prose diff через историю файлов.
- Анимации SVG/GIF/APNG/WebP, тема через picture и статичный reduced-motion вариант.
- github.dev, ручная Actions-лаборатория, обычные Markdown-состояния.

Новый бесконечный typing SVG, contribution snake или бейдж не добавлен: это снова картинка/анимация, а пользователь просит более сильную возможность.

## Источники и границы исследования

[Десять просмотренных файлов с постоянными SHA и URL](samples/capability-research/sources.json): два документа GitHub, три файла CLI и пять файлов четырёх проектов игр. Файлы CLI/PHP и короткие README прочитаны как исходный текст, не исполнялись; большой документ non-code просмотрен по относящимся к задаче разделам. Внешние сайты и игровые серверы не открывались. Поиск включал также подборки профилей, typing SVG, terminal SVG, video и STL diff; выдача поиска не считается аудитом найденных репозиториев.

В этом проходе нет новых runtime-зависимостей, workflows, генерации изображений, облачных запусков и обещания браузерной проверки. Следующий осмысленный экспонат — видео **после** реальной загрузки и проверки, а не ещё один текстовый «плеер».
