# GitHub как интерфейс: форма и rich diff

[← README](../README.md)

Продолжение поиска **необычных возможностей самой платформы**, не очередная иллюстрация. Два опыта открываются на github.com. Они не являются iframe внутри README и не требуют отдельного приложения на Pages.

## 1. YAML становится настоящей формой

[Открыть песочницу](https://github.com/overbaffe1/gitEdit/issues/new?template=native-playground.yml)

Это страница **создания Issue** с нативными элементами GitHub. Для неё может понадобиться вход в аккаунт. Открытие ссылки само по себе не отправляет Issue. Чтобы просто изучить форму, ничего публиковать не нужно.

| Элемент | Что попробовать | Что на самом деле происходит |
|---|---|---|
| Markdown-панель | Прочитать предупреждение сверху | Статический текст формы, не включаемый в отправленные ответы |
| Input | Ввести вымышленный позывной | Изменяется текстовое поле; это не поиск и не запрос контактов |
| Dropdown | Выбрать README, файл или историю | Одиночный выбор из фиксированных вариантов |
| Multiple dropdown | Выбрать несколько механик | Множественный выбор; не динамическая фильтрация остальных полей |
| Textarea | Набрать вымышленную заметку | Обычный редактор текста; интерфейс Markdown зависит от GitHub |
| Textarea с `render: json` | Изменить пример JSON | **Только оформление ответа кодовым блоком после отправки**, не валидация JSON и не выполнение кода |
| Checkboxes | Включать и выключать отметки | Настоящие редактируемые элементы формы, в отличие от disabled task-list в README |
| Required | Найти обязательные поля и подтверждение | Условия отправки GitHub, не произвольная бизнес-логика на JavaScript |

Форма построена из [`.github/ISSUE_TEMPLATE/native-playground.yml`](../.github/ISSUE_TEMPLATE/native-playground.yml). Старый шаблон `readme-block.yml` и конфигурация выбора шаблонов не изменены. Новый шаблон становится доступен через обычный выбор Issue template после попадания в default branch.

### Предзаполнение по ссылке

[Та же форма с вымышленным позывным](https://github.com/overbaffe1/gitEdit/issues/new?template=native-playground.yml&callsign=%D0%9B%D1%83%D0%BD%D0%BD%D1%8B%D0%B9+%D0%B0%D1%80%D1%85%D0%B8%D0%B2%D0%B0%D1%80%D0%B8%D1%83%D1%81)

В query передаётся `callsign`, совпадающий с `id` поля. Документация схемы называет `id` каноническим идентификатором для URL prefills. Это не API отправки формы; вход в аккаунт и переходы интерфейса могут влиять на сохранение параметров.

Нельзя помещать в такую ссылку токены, email, адреса и другие приватные значения: query виден в адресной строке и может попасть в историю/логи. В нашем примере только вымышленный позывной.

### Безопасно закончить опыт

**Просто закрыть страницу, не отправляя форму.** Не надо нажимать Create/Submit issue ради теста. Если обязательные условия выполнены, это создаст настоящую публичную запись. В этом изменении ни тестовый Issue, ни комментарий не публиковались.

Не вводи секреты, личные данные и не прикрепляй приватные файлы. Загрузка вложений в GitHub может начаться до отправки формы. Не обещаем отсутствие сетевых запросов, сохранение/удаление черновика при закрытии или анонимность редактирования. Здесь нет автоматической отправки и не добавляются workflows, labels, assignees, Projects или вебхуки. В другом репозитории отправка Issue может запустить уже настроенные автоматизации.

Это не конфигуратор, который пересчитывает сцену, не калькулятор и не интерактивная игра. YAML задаёт поля; GitHub переводит отправленные ответы в Markdown-тело Issue. Пользовательский JS, условные ветки формы, запросы к нашим сервисам и запись в файлы не добавлены.

## 2. Изменения в документе, а не только в Markdown-коде

Постоянная ссылка на коммит находится в начале README, в новом блоке «Пульт GitHub». В нём меняется **только один короткий Markdown-файл** — [карточка экспоната](../assets/github-controls/revision.md).

В интерфейсе diff выбери значок **Display the rich diff / Rendered**, если он доступен. Переключись обратно в Source и сравни:

- фразу «статичная картинка» заменили на «нативная интерактивная карта»;
- в таблице изменены управление и формат, добавлена строка;
- в нумерованном списке теперь три шага вместо двух;
- добавлена новая заметка с жирным вводным текстом.

Все изменения учебные, а не журнал действительного преобразования чужой картинки в карту. В Git действительно сохранены две разные версии файла; это не нарисованные красные и зелёные подписи. [Параметры с SHA коммита](samples/github_controls/config.json) позволяют восстановить точную ссылку.

По документации GitHub rich diff умеет также отмечать невидимые изменения атрибутов, например URL ссылки, через подсказку. Но это не означает, что любое сложное HTML-содержимое корректно сравнимо: для полноты стоит смотреть и Source. Построчные комментарии к изменениям добавляются в source view; rich diff не подменяет весь code review.

Rendered diff может быть недоступен для слишком больших/сложных изменений, в отдельных интерфейсах или для неподдерживаемой разметки. Поэтому пример короткий. Его текущую версию также можно открыть [как обычный документ](../assets/github-controls/revision.md) или [как исходник](../assets/github-controls/revision.md?plain=1), но это не заменяет сравнение версий.

## Где проходят границы

| Опыт | Где работает | Не следует обещать |
|---|---|---|
| Issue Form | Страница создания Issue на GitHub | Встроенную форму внутри README; отсутствие входа в аккаунт |
| Предзаполнение | Query-параметры ссылки на ту же форму | Отправку запроса или выполнение кода; хранение приватных данных |
| Rich diff | Коммит/PR с изменением документа | Постоянное наличие режима в любом клиенте GitHub |
| Readme entry points | Обычные Markdown-ссылки | Что нарисованная кнопка стала встроенным приложением |

STL, карты и Mermaid в предыдущем стенде по-прежнему находятся **внутри README**. Эти два новых опыта — другие страницы GitHub. Визуальная галерея и весь прежний текст сохранены.

## Что исследовано

Относящиеся к задаче разделы четырёх официальных документов `github/docs`:

1. Issue Forms: расположение YAML, преобразование ответов в Markdown и поддерживаемый контекст.
2. Form schema: типы markdown/input/dropdown/textarea/checkboxes, required, multiple, render и URL-prefill по id.
3. Common validation errors: обязательные ключи, уникальность id и ошибки структуры.
4. Non-code files: source/rendered prose diff, атрибуты, ограничения и комментарии.

[Постоянные SHA и URL](samples/github_controls/sources.json). Произвольные сторонние формы и исходники GitHub не копировались. Upload-поле с условной доступностью из новых версий схемы не используется; установленная здесь форма ограничена основными документированными типами. Репозиторий имеет включённые Issues; Discussions при проверке выключены, поэтому опросы не включались и настройки репозитория не менялись.

## Проверка и воспроизведение

```sh
python -m pip install PyYAML
python atlas/samples/github_controls/generate.py
python -m unittest discover -s tests -p test_github_controls.py -v
```

Генератор создаёт блок ссылок, JSON механик и контрольные суммы. Он не редактирует README/форму, не выполняет сеть, не создаёт Issue и не делает коммиты. Исторические ревизии карточки уже находятся в Git; генератор не переписывает историю.

Тесты проверяют структуру формы и ограничения выбранного поднабора схемы, уникальные id, URL-prefill, предупреждения о публикации, реальные версии файла в истории, сохранение предыдущего README и перегенерацию. Это **собственные структурные проверки, не официальный endpoint валидации GitHub**. Markdown API дополнительно проверяется на сохранение ссылок.

Авторизованный интерфейс формы, фактическое отображение rich diff и поведение входа в аккаунт в браузере среды не проверялись. Ни отправка формы, ни нажатие кнопки публикации не нужны для проверки файлов и намеренно не автоматизируются.
